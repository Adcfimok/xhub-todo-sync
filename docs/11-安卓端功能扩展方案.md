## 1. 待办提醒时间：预设 + 自定义

### 实现思路

提醒时间必须是**绝对时间戳**，不能只存「提前 N 分钟」——否则用户想「今晚 8 点提醒我，但截止是明天」时无法表达。但只存绝对时间又有个坑：改了截止日期，提醒还停在旧日期上。

所以用**两个字段并存**，职责分开：

| 字段 | 含义 | 谁维护 |
| --- | --- | --- |
| `remindAt` | 提醒触发的绝对毫秒时间戳；调度器只认这个 | 保存时计算 |
| `remindLead` | 0 = 自定义绝对时间；>0 = 跟随 `dueAt` 提前 N 分钟 | 选预设时写入 |

`dueAt` 变更时：若 `remindLead > 0`，重算 `remindAt = dueAt - remindLead*60000`；若 `remindLead === 0`，保持 `remindAt` 不动（用户明确指定了时刻，不该被截止时间牵走）。

### 改动点

| 文件 | 位置 | 改什么 |
| --- | --- | --- |
| `service/store.js` | `FIELD_LIMITS`、`KEEP.todos`、`normalizeRecord` | 白名单加 `remindLead`（`remindAt` 已有，见 `:821`/`:875`），上限 10080（7 天） |
| `lib/todoform.js` | `fields` | 在「时间」后插入一行「提醒」：`type:'chips'` + 条件展开 `date`/`time` |
| `lib/todoform.js` | `onSave` | 根据选择算 `remindAt`/`remindLead`；`base` 存在且 `dueAt` 变化时按上表重算 |
| `lib/ui.js` | `openForm` | 新增 `type:'chips'` 渲染分支（现值 + 选中态 + 点击回调），现在只支持 `date/time/select/textarea/text/number`（`:74-90`） |
| `lib/alerts.js` | `checkTodos` | 改为遍历 `remindAt`，保留 `dueAt-15min` 作为无 `remindAt` 老数据的回落 |
| `pages/todos.js` | 行渲染 | 有 `remindAt` 行尾加铃铛图标 + 时刻，让「提醒」可见（现在只显示 `dueAt`） |
| `pages/calendar.js` | 日视图行 | 同上，小铃铛 |

### 交互流程

```
新建/编辑待办
  └─ 提醒  [不提醒] [提前30分钟] [1小时] [1天] [3天] [7天] [自定义…]
        ├─ 点预设 → 下方灰字实时显示「将在 11月8日 14:30 提醒」
        └─ 点自定义 → 展开「日期 + 时间」两个原生输入
保存
  └─ 无截止时间且选了预设 → 提示「预设需要先设截止时间」并聚焦日期（不静默改成别的值）
```

预设值固定为 `[30, 60, 1440, 4320, 10080]` 分钟，与需求给的 30 分/1 时/1 天/3 天/7 天一一对应。展示时按量级换单位（30 分钟 / 1 小时 / 1 天…），不显示「1440 分钟」。

### 异常与边界

- **提醒时间已过去**：允许保存，但在面板上标红「该时间已过，保存后会立即提醒一次」；调度器有 10 分钟宽限窗，不会无限补发。
- **提醒晚于截止时间**：不阻断，行内提示「提醒晚于截止时间」，因为「催我确认已完成」是合理用法。
- **无截止时间 + 自定义时间**：完全允许，`remindAt` 独立生效（这是「独立闹钟」语义）。
- **跨天/时区**：一律 `new Date(y, m-1, d, hh, mm)` 本地构造，与 `todoform.js:63-70` 现有 dueAt 构造方式一致，不引入 UTC 换算。
- **重复待办**：`repeatMode !== 'once'` 时，完成一条后应由重复逻辑重算下一次 `dueAt` 与 `remindAt`。当前 `repeatMode` 在手机端未生效（只在字段里存着），本期不做，但在代码注释里标注这个前提，避免以后加重复功能时漏掉提醒。
- **去重键**：`notifiedMap` 的 key 从 `id@dueAt` 改为 `id@remindAt`，改了提醒时间即视为新提醒。

### 验收

1. 设「提前 30 分钟」→ 关掉重进 → 面板仍显示选中「提前 30 分钟」，且灰字时刻正确。
2. 改截止时间 → 提醒时刻跟着变（因为 `remindLead>0`）。
3. 「今晚 20:30」自定义 + 截止明天 → 改截止到后天，提醒仍在今晚（因为 `remindLead===0`）。
4. 造一条 `remindAt = now + 30s` 的待办，前台等 30 秒 → 收到通知且只收到一次。

## 2. 笔记 / 速达 / 提示词：可编辑的新增与删除

### 先说结论：能力都在，坏在入口

三个页面的增删**代码已经完整**：

- 新增：`notes.js:14`/`snippets.js:13`/`resources.js:24` 都调 `setQuickAdd(() => edit(null))`，接底栏加号
- 编辑：整卡点击（笔记 `:50`、提示词 `:53`），速达靠 `oncontextmenu`（`resources.js:53`）
- 删除：`openForm` 的 `onDelete` → `softDelete`（`ui.js:113-117` 渲染删除按钮）

真实问题有三个：

1. **速达的编辑入口在 Android WebView 里根本不触发**。移动版 Chrome/WebView 不派发 `contextmenu`，长按走的是系统文本选择/图片保存菜单。也就是说速达**只有新增，没有编辑和删除**——这与用户反馈完全吻合。
2. **笔记/提示词的编辑靠「点整张卡」，没有任何视觉提示**，用户不知道能点。
3. **删除按钮在 sheet 最底部**，有键盘时容易被顶出可视区，且删了不能撤销。

### 改动点

| 文件 | 位置 | 改什么 |
| --- | --- | --- |
| `lib/ui.js` | 新增 `itemMenu(items)` | 通用「⋯」动作面板：编辑 / 删除 / 复制 / 置顶，复用 `modal-mask` + `modal` |
| `lib/ui.js` | 新增 `undoToast(msg, onUndo)` | 带「撤销」按钮的提示条，5 秒后消失 |
| `pages/notes.js` | 卡片结构 | 右侧加 `⋯` 按钮（`stopPropagation`），点击开 `itemMenu` |
| `pages/resources.js` | 卡片 | **去掉 `oncontextmenu`**，改为右下角 `⋯`；`kind==='web'` 时菜单多一项「打开」 |
| `pages/snippets.js` | 卡片 | 右侧 `⋯`；原有「复制/置顶」两个 mini 按钮收进菜单，减少视觉噪音 |
| 三个页面 | `onDelete` | 改为 `softDelete` + `undoToast('已删除', () => touch(rec, {deleted:false}))` |
| 三个页面 | 列表头 | 搜索框右侧加圆形「＋」，不依赖底栏加号（二级页返回后加号语义会变） |

### 交互流程

```
列表页
  ├─ 点「＋」（搜索框右）  → 新建面板
  ├─ 点卡片主体          → 编辑面板
  └─ 点「⋯」             → 动作面板
        ├─ 编辑  → 同一个编辑面板
        ├─ 删除  → 确认框 → 软删除 → 底部提示「已删除 [撤销]」
        └─ 复制/置顶（按集合可用性）
```

删除后立即从列表消失（`colRecords` 已过滤 `deleted`），撤销时 `touch(rec,{deleted:false})` 会生成新的 HLC，自然在同步时胜出，不需要特殊协议支持。

### 异常与边界

- **撤销窗口内切页**：`undoToast` 的定时器挂在 `document` 上而非页面节点，切页不丢；5 秒后提示消失，删除生效（已经是软删除，无额外动作）。
- **撤销后又想删**：重新点「⋯ → 删除」即可，不冲突。
- **速达非 web 类型**：菜单里「打开」置灰并提示「文件与程序只能在电脑上打开」，与 `resources.js:73` 现有行为一致。
- **空列表**：空态文案带明确动作（「点右上＋新建第一条」），现在的 `emptyBlock` 只说「还没有笔记」。
- **长按兼容**：保留 `oncontextmenu` 作为桌面浏览器的附加入口（`e.preventDefault()` 后开菜单），移动端靠按钮，两条路都通。

### 验收

1. 速达页：新建 → 点 ⋯ → 编辑 → 改名保存 → 列表更新（**这条现在必然失败**）。
2. 速达页：点 ⋯ → 删除 → 确认 → 消失 → 点撤销 → 恢复。
3. 笔记/提示词：同样流程通过；键盘弹出时删除按钮仍可点（`sheet-body` 需 `max-height: 60vh; overflow-y:auto`，把删除按钮固定在 `sheet` 底部而非 `body` 内）。

## 4. 通知强提醒：通知 + 震动 + 应用内弹窗

### 先说清楚现状与硬约束

已有（`MainActivity.java`）：`IMPORTANCE_HIGH` 渠道 + `enableVibration(true)`（`:157-160`）、Android 13+ 运行时权限自动申请（`:164-168`）、`notify()` 发通知（`:393`）、`vibrate()`（`:482`）。**这些够用，不用重写。**

真正缺的两件事：

1. **App 不在前台时不会提醒**。`alerts.js` 靠 `setInterval(sweep, 30s)`（`:20`），WebView 一进后台，JS 定时器被系统冻结甚至销毁，提醒就没了。这是「提醒不准」的根本原因，不是通知渠道的问题。
2. **通知点了只回首页**。`PendingIntent` 没带任何 extra（`:399-403`），用户点开还得自己找是哪条待办。

### 改动点

| 层 | 文件 | 改什么 |
| --- | --- | --- |
| 原生 | 新增 `ReminderScheduler.java` | 用 `AlarmManager` 在 `remindAt` 时刻唤醒，发通知；`setAndAllowWhileIdle` 兜底，有精确闹钟权限时用 `setExactAndAllowWhileIdle` |
| 原生 | 新增 `ReminderReceiver.java` | `BroadcastReceiver`：读 extra（标题/正文/待办 id/路由）→ 建通知 + 震动 |
| 原生 | `MainActivity.java` | 新增 `@JavascriptInterface syncReminders(String json)`：JS 把未来 24 小时的提醒列表整体下推，原生按 id 增删 alarm（幂等覆盖） |
| 原生 | `MainActivity.java` 通知 | `PendingIntent` 加 extra `route=todos`、`todoId=…`；`onNewIntent` 读出来 → `evaluateJavascript("location.hash='#/todos'")` + 高亮该条 |
| 原生 | `AndroidManifest.xml` | 加 `SCHEDULE_EXACT_ALARM`（可选申请）、`RECEIVE_BOOT_COMPLETED` + `BOOT_COMPLETED` 接收器（重启后重建闹钟） |
| JS | `lib/alerts.js` | 每次 `sweep()` 后调 `syncReminders()` 把 24h 内的 `remindAt` 列表交给原生；前台仍保留自身 tick 做「应用内弹窗」 |
| JS | 新增 `lib/overlay.js` | 应用内强提醒浮层：顶部滑入卡片（标题 + 时间 + 「稍后 10 分钟 / 完成 / 关闭」），不遮输入框（复用 `--dock` 变量定位） |
| JS | `pages/settings.js` | 提醒卡片拆成三个开关：待办提醒 / 番茄钟提醒 / 强提醒（震动+浮层）；加「通知权限」「后台限制」两行状态检查 |

### 强提醒的分级策略

| 场景 | 表现 |
| --- | --- |
| App 在前台 | 应用内浮层（3 秒自动收起到顶部条）+ 震动 200ms + 系统通知 |
| App 在后台 | 系统通知（heads-up）+ 震动 + 提示音 |
| 锁屏 | 系统通知点亮屏幕（渠道已 HIGH）；**不用** `fullScreenIntent` |
| 用户点通知 | 直接进待办页并高亮该条 |

**为什么不用全屏 Intent**：Android 14 起 `USE_FULL_SCREEN_INTENT` 只对闹钟/通话类应用开放，普通应用申请会被拒、调用被降级成普通通知。做成「开屏弹全屏」在真机上大概率不生效，反而让人以为功能坏了。用 heads-up + 应用内浮层是可达的等价方案。

### 异常与边界

- **精确闹钟权限被拒**（Android 12+）：降级 `setAndAllowWhileIdle`，误差通常 1-10 分钟。设置页显示「当前为省电模式，提醒可能延迟几分钟」并给「去开启精确闹钟」入口。
- **Doze 限流**：`setAndAllowWhileIdle` 在深度 Doze 下约每 9 分钟才放行一次。方案是「到点前 1 分钟也挂一个 alarm 做预热」，且提醒时间 < 未来 15 分钟的才用精确闹钟，远的用普通 alarm + 后台重建。
- **厂商省电**（小米/华为/OPPO/vivo）：自启动与后台白名单无法用代码绕过，只能检测（`ActivityManager.isIgnoringBatteryOptimizations`）+ 引导页。文案要写具体路径，不要写「请关闭省电优化」。
- **免打扰模式**：渠道 HIGH 也会被 DND 静音。设置页加一行说明，不假装能突破。
- **重启手机**：`BOOT_COMPLETED` 重建未来 24h 的 alarm；超过 24h 的靠每日首次打开 App 时补推。
- **时区/系统时间变更**：`ACTION_TIME_CHANGED` / `ACTION_TIMEZONE_CHANGED` 也触发重建。
- **权限被永久拒绝**：`shouldShowRequestPermissionRationale` 为 false 时不再弹系统框，改为跳应用设置页。
- **通知去重**：原生侧用 `todoId + remindAt` 的 hash 做 notification id，同一提醒重复调度不会叠出两条。

### 验收

1. 造 `remindAt = now+60s` 的待办 → 锁屏 → 60 秒后收到 heads-up + 震动。
2. 点通知 → 直接进待办页且该条高亮。
3. App 前台时 → 出现应用内浮层，点「稍后 10 分钟」→ 10 分钟后再提醒一次。
4. 重启手机 → 未到点的提醒仍能触发。
5. 关闭「强提醒」开关 → 只有通知，无震动无浮层。

## 5. AI 助手「不会建待办」：根因与修复

### 根因（已实证，不是推测）

手机端 AI 的流式响应由 `lib/agent.js` 自己解析，桌面端走 Rust 侧实现，**两套代码**。所以同一模型在 PC 上能建、手机上不能。

问题出在 `agent.js:335-374` 这段解析，有四个缺陷：

```js
buf += chunk
const parts = buf.split('\n\n')            // ① 只认 \n\n
buf = parts.pop()
for (const part of parts) {
  const line = part.split('\n').find(...)  // ② 只取第一行 data:
  ...
}
// ③ 结束时没有 flush 残留 buf
// ④ 没有非流式兜底
```

后果链：**解析不出事件 → `toolCalls` 恒为空 → `runAgent` 在 `:432` 直接 return → 模型收不到工具结果、界面只显示一句聊天 → 用户看到「AI 只说话不做事」**。

用 `_tools/sse-parse-probe.mjs` 跑了 7 种真实分帧形态，现状实现**失败 4 种**：

| 用例 | 现状 agent.js | 方案实现 |
| --- | --- | --- |
| 官方 `\n\n`，tool 参数分两片 | 解析出 1 个 | 解析出 1 个 |
| 中转 `\r\n\r\n` | **解析 0（残留 160B）** | 解析出 1 个 |
| 唯一一条事件、结尾无空行 | **解析 0（残留 141B）** | 解析出 1 个 |
| 中转忽略 `stream`，回完整 JSON | **解析 0（残留 112B）** | 解析出 1 个 |
| tool 事件有空行、`[DONE]` 没有 | 解析出 1 个 | 解析出 1 个 |
| 事件被 TCP 切成两半 | 解析出 1 个 | 解析出 1 个 |
| 同一事件内多行 `data:` | **解析 0** | 解析出 1 个 |

`\r\n\r\n` 这条最关键：OpenAI / DeepSeek 官方用 `\n\n`，但经过 Cloudflare 或多数中转网关后可能变成 `\r\n\r\n`。**手机端一旦配的是平台中转，就一个事件都收不到。**

### 修复

| 位置 | 改法 |
| --- | --- |
| `agent.js:340` | 先 `buf = buf.replace(/\r\n/g, '\n')` 再按 `\n\n` 切（比正则切分更省，且不影响已累积内容） |
| `agent.js:342` | 改成收集块内**所有** `data:` 行，按 `\n` 拼接后解析（SSE 规范允许续行） |
| `agent.js` 请求结束处 | `.then()` 里先 flush：`if (buf.trim()) handleEvent(buf)` |
| `agent.js` 分发处 | 抽成纯函数 `parseSseBlock(text)`，可单测；`streamOnce` 只负责累积与调用 |
| `agent.js` 兜底 | 一个事件都没解析出来但拿到了内容 → 尝试 `JSON.parse(整体)`，按 `choices[0].message`（非流式）取值 |
| `agent.js` 错误可见化 | 上述都失败且 `rawBytes > 0` → 抛出「响应格式无法识别：上游可能不支持流式（返回的不是 SSE）」而不是静默返回空 |
| `agent.js` 模型能力检测 | `runTest`（`ai.js:544`）增加一次带 `tools` 的探针请求；400 且 message 含 `tool`/`function` → 提示「该模型不支持函数调用，换 deepseek-chat / gpt-4o-mini 等」 |
| `pages/ai.js` | `runAgent` 返回后若 `!ai.content && !ai.tools.length` → 不再显示「（没有返回内容）」，改显示具体原因 + 「换个模型试试」按钮 |

**顺带修一个同源问题**：`streamOnce` 里 `usage` 只在 `obj.usage` 出现时更新，而 `stream_options.include_usage` 在部分中转会被忽略，导致 token 统计一直空白——不影响建待办，但会被误认为「请求没发出去」。方案：拿不到 usage 时显示「—」而不是留空。

### 验证

- 新增 `android/tests/ai-parse.test.mjs`：把 7 种形态固化为断言，要求 `parseSseBlock` 全通过（修复前 4 种会红）。
- 真机三步验证：① 平台中转（`\r\n\r\n`）→ 说「明天下午三点交房租」→ 待办出现；② 直连 DeepSeek → 同样成功；③ 换一个不支持 tools 的模型 → 提示清晰，不静默失败。

### 已落地（2.9.2）

本项已修复并出包，不是待办：

| 改动 | 位置 |
| --- | --- |
| 抽出 `parseSseBlock` / `parseSsePayload`（delta 与 message 同一出口） | `lib/agent.js:337-392` |
| 抽出 `createSseParser`（累积 → `\r\n` 归一化 → 按空行切 → flush 残留） | `lib/agent.js:398-414` |
| 非流式整包兜底、坏响应显式报错 | `lib/agent.js:345-355`、`:495-500` |
| 18 项解析断言，修复前 4 项失败、修复后 18/18 通过 | `android/tests/ai-parse.test.mjs` |
| `versionCode 15 / 2.9.2`，签名不变可覆盖安装 | `todo-link-2.9.2.apk` |

`_tools/sse-parse-probe.mjs` 保留作缺陷形态存档：它的 legacy 分支复刻的是修复前逻辑，用来证明「为什么以前建不了待办」，不参与当前代码路径。

### 注意事项

- **不要改成「先请求一次非流式再请求流式」**：翻倍计费，且工具调用拿不到增量。
- **不要在 `onChunk` 里做 JSON.parse 全文**：`buf` 会越来越大，O(n²)。
- 修复后要确认 **PC 端不受影响**：桌面端不引用这段代码，改的是手机端独有实现。

## 6. 番茄钟：自定义时长

### 实现思路

时长配置存 `meta.pomoCfg = { focusSec, breakSec }`，默认 `{1500, 300}`。`pomState` 只存运行态（`mode/running/endAt/left/done`），不存配置——否则两份配置会打架。

### 改动点

| 文件 | 位置 | 改什么 |
| --- | --- | --- |
| `pages/pomodoro.js` | `:7-8` `FOCUS`/`BREAK` | 改为读 `pomoCfg` 的函数 `dur(mode)`（`:15-17` 已有 `dur`，把常量换成配置） |
| `pages/pomodoro.js` | `:116-129` 段控 | 「专注 25 分钟」文案改为动态；下方新增一行「时长设置」按钮 |
| `pages/pomodoro.js` | 新增 `openDurationSheet()` | 专注：5/15/25/45/60 分钟 + 自定义（1-180）；休息：3/5/10/15 + 自定义（1-60） |
| `lib/alerts.js` | `:85,87` | `total` 与完成文案改为读 `pomoCfg`，不再写死 `5*60`/`25*60`/「25 分钟完成」 |
| `lib/core.js` | `saveMeta` | 无需改，`pomoCfg` 走现有 meta 通道 |
| `pages/settings.js` | — | 不重复放设置项，只在番茄钟页内配置（就近原则） |

### 交互流程

```
番茄钟页
  ├─ 时长设置 ──→ 面板
  │    专注  [5] [15] [25] [45] [60] [自定义 __ 分钟]
  │    休息  [3] [5] [10] [15] [自定义 __ 分钟]
  │    未运行 → 保存后立即按新时长重置剩余并重绘
  │    运行中 → 保存后弹「按新时长重新计时？」[重新计时] [保留当前]
  └─ 开始 / 暂停 / 重置（逻辑不变）
```

### 异常与边界

- **运行中改时长**：不能无声无息改——用户可能已经跑了 20 分钟。默认「保留当前」，只有用户点「重新计时」才重置。
- **自定义输入非法**：空白/0/负数/非数字 → clamp 到 1-180（专注）、1-60（休息），并 toast 说明被调整后的值。
- **超长时长**（如 180 分钟）：`endAt` 靠系统时间算，App 被杀也能算准；但**到点提醒依赖第 4 项的闹钟**，否则后台不触发。方案里两项要一起做，不能只做这个。
- **切模式**：专注 ↔ 休息切换时按各自配置重置，`left` 取新时长（`:154-158` 现有逻辑，只需把 `dur` 换成配置）。
- **已完成计数**：`done` 不受配置影响，不清零。

### 验收

1. 改成专注 45 分钟 → 环形与数字显示 45:00，开始后倒计时正确。
2. 跑到一半改成 60 分钟并选「保留当前」→ 剩余时间不变。
3. 改成休息 3 分钟 → 到点通知文案是「休息结束」，不是「25 分钟完成」。
4. 自定义输入 `999` → 被 clamp 到 180 并提示。

| 类别 | 来源方式 | 原因 |


一键添加走 `newRecord('todos', { title, dueAt, remindAt, remindLead: 1440 })` + `touch`。

### 异常与边界

- **重复添加**：添加前按 `title` 与同一天的 `dueAt` 查重，命中则 toast「这条已经加过了」并跳到该条，而不是静默建重复。
- **已过节日**：默认不显示未来列表里的过去项，切「全部」可见，且「添加到待办」按钮置灰。
- **年表未覆盖的年份**（如 2036）：该年农历节日不显示，页面顶部提示「该年份数据待补」，节气与固定公历节日照常显示，不整页空白。
- **农历闰月**：年表直接给日期，不涉及闰月计算；若某年有闰月导致日期特殊，以年表为准。
- **除夕**：单独作为一条（农历十二月最后一天），与春节相邻两天，列表里要能同时看到。
- **时区**：日期按本地时区构造，出国改时区后日期不变（因为是「某年某月某日」的本地日期语义）。
- **批量添加**：不做「一键添加今年全部」——一次建 20 条会刷屏，且用户多半只关心最近两三个。留一个「按分类批量」作为后续可选项，本期不做。

### 验收

1. 三个分类切换，条目数正确（节气恒 24 条/年）。
2. 点「春节」添加 → 待办列表出现该条，`dueAt` 与年表一致，提醒提前 1 天。
3. 同一条再点一次 → 提示已存在，不产生重复。
4. 切到未覆盖年份 → 有明确提示且不崩溃。
5. `festival-check.mjs` 全绿。

## 8. 首页显示当前时间（精确到秒）

### 实现思路

时钟必须**独立于页面重绘**。`home.js` 的 `render()` 会被 `onChange` 触发（同步一有变化就整页 `innerHTML=''` 重建），如果时钟跟着 `render()` 走，要么每秒重建整页（滚动位置丢失、手势中断），要么时间停住。

所以：`render()` 里只建一个空节点 `<span id="hero-clock">`，由独立的 tick 循环只改它的 `textContent`。

### 改动点

| 文件 | 改什么 |
| --- | --- |
| `pages/home.js` | `hero` 增加 `hero-clock` 节点；`mount` 启动 tick、返回的清理函数里 `clearTimeout` |
| `pages/home.js` | `tick()`：`const now = new Date()` → 写 `HH:mm:ss`；同时比较日期是否跨天，跨天才更新 `hero-d` |
| `pages/home.js` | 用 `setTimeout(tick, 1000 - (Date.now() % 1000))` 递归对齐整秒，不用 `setInterval`（后者会累积漂移，长时间后跳秒） |
| `pages/home.js` | `document.addEventListener('visibilitychange')`：回到前台立即 tick 一次（后台期间定时器被冻结，回来不能显示旧时间） |
| `app.css` | `.hero-clock`：`font-variant-numeric: tabular-nums`（等宽数字，避免每秒宽度跳动）；秒字号小一档、颜色降一级 |
| `app.js` | 无需改：切页会调 `mount` 返回的清理函数（`app.js:56-63`），tick 自动停 |

### 视觉与排版

```
11 月 7 日 · 周五
19:22:07          ← 主字号 34-38px，:07 用 60% 字号、次级色
晚上好
还有 3 件待办，今天到期 1 件
```

或者整串等权重的 44px 大字。两种都行，建议前者：秒在视觉上退一档，既满足「精确到秒」又不抢问候语的层级。

### 异常与边界

- **切走再切回**：清理函数停 tick，回来重新 `mount` 立即算一次，不显示陈旧时间。
- **后台超过 1 分钟**：`visibilitychange` 立即 tick，不会出现「停在 3 分钟前」。
- **跨天**：tick 里判断 `date` 变化才重写日期行，避免每秒动 DOM。
- **系统时间被修改**：`new Date()` 直接反映，无需额外处理；但**不要**用累加计数的方式算时间（累加会错）。
- **性能**：每秒 1 次 `textContent` 赋值，代价可忽略；关键是**不要**在 tick 里调 `render()`。
- **时区**：用本地时间（`getHours()`），不做 UTC 转换。

### 验收

1. 首页显示 `HH:mm:ss`，秒每秒跳一次，不跳秒不卡顿。
2. 切到别的页再回来 → 时间立即正确。
3. 按 Home 键退到后台 2 分钟再回来 → 时间立即正确，不是旧值。
4. 同步一条数据触发 `onChange` → 时钟不闪断、滚动位置不重置。

## 10. 风险与取舍

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 底栏改 5 格后高亮块错位 | `--tab-i` 位移公式依赖格数 | 用 `navbar-check.mjs` 加断言，5 视口实测 |
| 笔记入口断链 | 移出底栏后若「我的」没补，功能直接失联 | 三处补位，写进验收清单第 3 条 |
| 节日年表填错 | 用户会照错日期安排事情 | 只用核对过的年表；`festival-check.mjs` 逐条比对；未覆盖年份明确提示 |
| 后台提醒仍不可靠 | 厂商省电策略无法绕过 | 设置页做状态检测 + 具体引导；文案不承诺「必定准点」 |
| 精确闹钟权限被拒 | Android 12+ 需用户手动授权 | 降级 `setAndAllowWhileIdle`，误差 1-10 分钟，页面明示 |
| AI 修复引入回归 | 解析改动影响所有对话 | 7 种形态单测；真机走一遍平台中转 + 直连两条路 |
| 番茄钟长时长依赖闹钟 | 只做第 6 项、不做第 4 项，长时长后台不提醒 | 两项必须同一版本上线 |
