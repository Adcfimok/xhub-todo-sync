# 14 · 教务系统一键导入（3.2.0）

> 本文记录 3.2.0 把「教务系统一键导入」从占位框架做成可用功能的依据、实现分层与已知边界。
> 资料来源必须是真实文件，不引用推断或编造的校方地址。

## 1. 依据：WakeUp 课程表 6.5.2 的实际做法

参考材料：用户桌面 `C:/Users/zhou/Desktop/WakeUp课程表_6.5.2`（反编译 APK 目录）与其同名 zip。

### 1.1 直接证据：`assets/empty.html`（936 字节，纯文本，可复核）

原文（节录）：

> 显示这个页面是因为没有收录贵校的教务网址哦。请在上方输入网址后点「确定」，严格按照提示进行操作哦。点到课表的界面再点右下角导入呀。

由此可以确定该功能的真实交互链路，而不是「输入学号密码让 App 代登录」：

1. 学校教务网址由 App 收录，没收录时**允许用户输入网址**；
2. 在 App 自带浏览器里打开教务站点，**用户自己在教务页面登录**；
3. 用户自己导航到「课表」界面；
4. 点 App 提供的「导入」按钮，抓取**当前页**并解析。

### 1.2 旁证

- `assets/school_info_android_new.txt`（174,033 字节）是 base64 形态的密文，对应「学校 → 教务网址」收录库。**3.2.0 写作本文时未解密；3.4.0 已完整解密并内置，见 `docs/16-WakeUp学校列表内置.md`。**
- `assets/router_v3.json`（5,408 字节）是 `i.wakeup.fun` 的 Hybrid 页面路由表（`vip-wakeup` / `wakeup-core` 模块，含 `pages/schoolSetting/index`），是离线页面分发配置，不是课表解析脚本。
- `assets/empty.html` 里同时说明「严格按照提示进行操作」「点到课表的界面再点导入」，说明解析器面向的是**课表页 DOM**，不是登录接口。

结论（3.2.0 时）：要内置的是「流程 + 抓取 + 本机解析」，当时学校库还是加密资源，因此先把网址交给用户填。
**3.4.0 更新**：已按 `docs/16` 的解密链完整取出 3570 条学校与教务网址并内置进安卓端，上述「无法通用内置」的限制不再成立；网址仍需用户确认，因为它是第三方应用的离线快照。

## 2. 实现分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 原生浏览器 | `android/.../MainActivity.java` | 在同一个 Activity 上叠一层独立 WebView（`openEduImport` / `closeEduImport` / `captureEduPage`），顶部栏提供「‹ / 导入当前页 / ×」；返回键先回退网页再关层；Cookie、缩放、混合内容按需开启 |
| 原生 → 前端桥 | `lib/native.js` | `hasEduBrowser` / `openEduImport` / `closeEduImport` / `waitEduCapture`；`__nativeEmit('edu', …)` 分块接收（每块 24 KB），拼成完整源码 |
| 解析层（纯函数） | `lib/edu.js` | JSON / HTML → 课程数组；星期、节次、周次、单双周、教师、地点归一；去重并经 `normalizeCourse` 规整 |
| 页面 | `pages/timetable.js` | 教务类型提示、网址输入、操作说明、预览（前 12 条）、覆盖 / 追加、开学日期；两条粘贴源码兜底入口 |

抓取脚本只取 `document.documentElement.outerHTML` 与同域 `iframe/frame` 的文档，注入前把 `input[type=password]` 的 `value` 属性清空，单页上限 600,000 字符。源码只在内存中分块回传，**不落盘、不上传**。

## 3. 解析规则

| 输入 | 识别方式 |
| --- | --- |
| 教务导出 / 桌面「教学安排表.json」 | `course_name`、`weekday`/`day_of_week`、`period_start`/`period_end`/`periods`、`weeks`、`week_type`、`teacher`、`location` |
| 接口 JSON | 递归（≤4 层）找最像课程列表的数组，优先 `courses / kbList / data / rows / timetable` 等键；兼容 `kcmc / xqj / ksjc / jsjc / zc / jsxm / skdd` |
| 课表 HTML | 遍历所有 `<table>` 取识别课程最多的一张；表头「星期一…」建列→星期映射，第 0 列「1-2 / 3-4」建行→节次映射；单元格内按 `<br>` 分段提取课程名、周次、单双周、教师、地点 |
| 星期 | 「星期一 / 周三 / 星期日 / 3 / Friday / 0(周日)」→ 1..7；越界数字判为脏数据丢弃 |
| 周次 | `2-3,8-17` 拆成两段（模型一段只能存一个区间）；`1-16 单周`/`双周` → `weekType` 1/2；无周次默认 1-16 每周 |

用桌面真实的 `教学安排表.json`（含 `weeks: "2-3,8-17"`）实测：识别 **33 条**课程、**11 门**课，多段周次正确拆开，教师与教室保留。单测里用的是同结构脱敏样本，避免把学号姓名写进仓库。

## 4. 隐私与安全边界

- 账号密码只出现在教务系统自己的页面；Java 侧不给外部页面暴露任何 `@JavascriptInterface`，抓取走 `evaluateJavascript` 返回值（用 `JSONTokener` 解析），避免第三方页面调用原生能力。
- 教务浏览器是独立 WebView，与主页面（本地 AssetServer 的 `127.0.0.1`）不同源；主页面只允许本机 URL 跳转的规则不变。
- 抓取内容不写入文件、不进同步协议、不进 AI 上下文，解析后即丢弃。

## 5. 已知边界与兜底

- **3.4.0 起已内置学校库**：3570 条（3091 条带教务网址），可从「从学校列表选择」搜索并自动填网址；网址仍需用户确认（离线快照可能失效），也仍允许完全手动输入（协议缺省时补 `https://`，可显式写 `http://`）。详见 `docs/16`。
- 纯 JS 绘制、没有 `<table>` 的课表页，或一格塞多门不同周次课程的页面，可能识别不全；此时 UI 会提示并自动把源码带进「粘贴源码」框，也可手动录入。
- 登录页点「导入」识别不到课程是预期行为，提示会引导回到课表页再点一次。
- 浏览器预览环境没有原生桥，自动降级为「粘贴页面源码」，解析逻辑完全一致。
