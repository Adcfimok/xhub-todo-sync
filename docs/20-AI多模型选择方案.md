# 20 · AI 多模型接入与选择方案（3.8.0）

## 一、目标

把「AI 用哪个模型」从一组隐式配置（`aiPlatform / aiBase / aiKey / aiModel`）升级为**可选清单**：

1. AI 助手顶部与设置页都能看到当前模型，并能切换；
2. 清单同时容纳 **x-hub 内置模型**（平台额度）与**自备 OpenAI 兼容接口**，后续可继续添加；
3. 课表 AI 识别在真正发请求前必须让用户确认模型；
4. 明确默认值、生效范围、持久化位置，并处理模型不可用时的提示与回退。

## 二、数据模型与迁移

### 2.1 存储键（均在 `meta`，只存本机、不同步电脑）

| 键 | 形状 | 说明 |
| --- | --- | --- |
| `aiModels` | JSON 字符串：`[{id, kind, model, label, base?, key?, addedAt}]` | 全部可选模型。`kind` 为 `platform` / `custom` |
| `aiSelected` | 字符串 | 当前选择的 id：`pl:<模型名>` 或 `cu:<时间36><随机>` |
| `aiPlatformModels` | JSON 字符串 | 上次成功拉到的平台模型名，离线兜底 |
| `aiPlatformSyncAt` | 毫秒时间戳 | 上次平台清单对账时间（6 小时内不重复拉） |

自备模型的 API Key 仍以明文存在 `meta` 的 `aiModels` 里，与旧版 `aiKey` 的安全级别一致：只在 WebView 的 IndexedDB 内，不经过同步协议、不上传平台。

### 2.2 旧配置迁移

启动时 `ensureAiStore()` 执行一次：

| 旧状态 | 迁移结果 |
| --- | --- |
| `aiPlatform === '1'` 且有 `aiModel` | 生成 `pl:<模型名>`，并设为当前 |
| 自备：`aiBase` / `aiKey` / `aiModel` | 生成 `cu:*`，`label` 取接口主机名，设为当前 |
| 已登录但没有旧配置 | 用 `aiPlatformModels` 缓存铺出列表；没有缓存则等首次联网对账 |
| 已有 `aiModels` 但没有 `aiSelected` | 把默认模型显式写进 `aiSelected` |

同时继续双写旧键（`aiPlatform/aiBase/aiKey/aiModel`）：降到旧版 APK 仍能按原逻辑对话。平台模型只写 `aiPlatform='1'` 与 `aiModel`，**不会把账号 token 写进 `aiKey`**。

## 三、默认模型与生效范围

### 3.1 默认模型

`defaultProfile(profiles, loggedIn)`：

1. 已登录且有平台模型 → **平台清单第一条**（即 x-hub 内置默认）；
2. 否则 → **第一个自备模型**；
3. 都没有 → 返回空，页面给「添加模型 / 去登录」引导。

首次拉到平台清单时就写入 `aiSelected`，不让「默认」只停留在计算里。

### 3.2 切换后的生效范围

- **全局**：AI 助手对话、课表 PDF / 文字识别共用同一个当前模型；
- **立即**：选中即写盘，不依赖「保存」；下一次请求就用新模型；
- **持久**：`meta` 存在 IndexedDB，重启 App 后保留；
- **不跨设备**：`meta` 不参与同步，换手机需要重新选（自备 Key 也不应跨设备复制）。

## 四、界面与交互

### 4.1 AI 助手

- 顶部工具条左侧为**当前模型胶囊**（圆点区分平台/自备 + 名称 + 标签），点击打开模型选择器；
- 设置面板（⚙ →「模型设置」）：
  - 顶部「当前」摘要；
  - `x-hub 内置模型`：登录后列出平台清单，可刷新；未登录显示登录入口；
  - `自备模型`：列表 + 添加/编辑/删除；添加表单保留预设、测试连通、获取模型；
  - 系统提示词与「保存并关闭」；
  - 文案明确「模型选择即时保存并全局生效」。

### 4.2 模型选择器（`lib/modelpicker.js`）

- 分组展示：`x-hub 内置模型` / `自备模型`；
- 每行：名称、来源/接口主机、模型名；当前项高亮 +「已选」；
- 不可用项标红原因（缺少 Key / 需要登录），仍可点选查看原因，但确认按钮禁用；
- 顶部提示生效范围；存在回退时显示黄色横幅「原模型已不可用：…，已临时改用…」；
- 底部「使用这个模型」确认；登录状态下静默对账一次平台清单。

### 4.3 课表 AI 识别

两个入口都在真正识别前插入选择器：

- `AI 识别 PDF 课表`：先选模型 → 再选文件 → 本地判断文本层 / 渲染图片 → 请求；
- `粘贴文字让 AI 识别`：先粘贴 → 点「开始识别」→ 选模型 → 请求；取消选择时保留已粘贴内容。

进度卡片显示「模型：<名称>」；失败卡片提供「换一个模型再试」。

## 五、可用性与回退

### 5.1 可用性判定

| 类型 | 条件 | 不可用提示 |
| --- | --- | --- |
| 平台模型 | 已登录（`ptToken` 非空） | 需要登录 x-hub 账号 |
| 自备模型 | 有 `base`、`model`、`key` | 缺少接口地址 / 模型名 / API Key |
| 任意 | `model` 非空 | 模型名为空 |
| 无模型 | `profiles` 为空 | 还没有可用模型 |

### 5.2 回退顺序

`resolveRun(profiles, selectedId, opts)`：

1. 选中的模型存在且可用 → 直接用；
2. 否则按「默认模型 → 列表顺序」找第一个可用项；
3. 返回 `fallbackFrom` 与原因，由 UI 提示「原模型已不可用，已临时改用 X」；
4. 全部不可用 → `profile = null`，页面显示空态与原因，不静默失败。

触发场景：

- **所选模型被删除 / 平台下架** → 启动对账、选择器刷新、请求 400 都会落到新默认；
- **退出登录** → 平台模型回退到自备模型；没有自备则显示「需要登录」；
- **删除当前自备模型** → `removeModel` 立即选默认；
- **请求返回 `model_not_allowed`** → 重新拉平台清单，若当前模型已不在清单则切默认并**自动重试一次**；已经有流式正文时不重试，避免重复输出。

平台清单为**空**时视为服务端瞬时故障，不清空本地列表（只有非空清单才做「多退少补」）。

## 六、请求链路

| 类型 | baseURL | 鉴权 | 模型名 |
| --- | --- | --- | --- |
| 平台 | `https://x-hub.xfactor.top/v1` | `Bearer <账号 token>` | 清单中的模型名 |
| 自备 | 用户填写的地址（去尾斜杠） | `Bearer <自备 Key>` | 用户填写的模型名 |

两者都走 `POST <base>/chat/completions`。平台中转没有 `GET /v1/models`，平台模型清单只能走 `/api/v1/ai/models`；自备接口的「获取模型」才用 `GET /models`。

## 八、边界与取舍

- **平台模型能力不可知**：清单只有名字，无法判断是否支持图片。视觉识别失败时明确提示换带视觉的模型，由用户决定。
- **平台清单需要登录**：未登录时选择器只显示登录入口，不猜测模型名，避免选中后必然 400。
- **Key 明文**：与旧版一致，存在本机 IndexedDB；没有引入加密，因为密钥本身要参与请求，加密只能提高读取门槛，收益有限。
- **不做跨设备同步**：`meta` 不同步，模型清单与 Key 都留在本机。
- **平台模型顺序即优先级**：默认取清单第一条，服务端可通过调整顺序改变新装用户的默认模型。

### 9.2 真机步骤

1. 登录 x-hub 账号 → 进 AI 助手：顶部应显示平台清单第一条；设置页「x-hub 内置模型」应列出全部模型。
2. 点顶部模型 → 选另一条 → 发消息，抓包/服务端日志确认请求体的 `model` 已变。
3. 设置 → 添加自备模型（地址 / 模型名 / Key）→ 保存后应自动切过去；杀掉 App 重开仍是它。
4. 退出账号 → 再进 AI：应自动回退到自备模型并提示；若没有自备模型，应显示「需要登录」而不是报错。
5. 课表 → 导入 → AI 识别 PDF：应先出现「选择识别模型」，点取消不应选文件、不应发请求；确认后才进入文件选择。
6. 平台后台下架当前模型 → 重新打开选择器刷新：应自动切到剩余模型；或直接发消息，应自动重试一次并成功。
