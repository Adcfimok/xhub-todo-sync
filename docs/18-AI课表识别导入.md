# AI 自动识别课表导入（PDF）

## 一、这个功能解决什么

教务系统导出的课表 PDF 版式五花八门：有的是标准 7 列网格，有的是「上午/下午」分段，
有的把两门课塞进同一格，还有整页是截图的扫描件。用固定规则解析必然漏，
所以这一版把「看懂版式」这件事交给 AI，把「保证数据干净」留给自己。

入口：我的 → 课表 → 导入 → **AI 识别 PDF 课表**。

## 二、为什么不直接抽 PDF 文字就完事

Android 没有公开的 PDF 文本提取 API（`PdfRenderer` 只会画位图）。
自己写抽取器能覆盖电子版 PDF，但有两个绕不过去的坑：

1. **中文 CID 字体**：`Identity-H` 编码下文字是字形编号，必须靠字体里的
   `ToUnicode` CMap 才能还原成汉字；缺映射就是一堆方块。
2. **表格结构在文字流里是平的**：文字顺序未必等于视觉行列，
   光有文本、没有坐标，很难还原「星期 × 节次」的二维关系。

所以最终做成**两条链路，自动选**：

| 条件 | 走哪条 | 输入给模型 |
| --- | --- | --- |
| 文本层够长、够干净、含中文 | 文本模式 | 抽取出的文字（保留换行） |
| 文本层缺失/乱码/像扫描件 | 图片模式 | 每页渲染成 JPEG，内联成 data URL |

判定阈值写在 `pages/timetable.js`：`chars ≥ 40`、`quality ≥ 0.6`、`cjk ≥ 8`。
不达标就不把乱码喂给模型，直接换图片 —— 宁可多花一点 token，也不要一张脏课表。

## 三、链路

```
选 PDF（系统选择器，application/pdf）
  ↓
PdfIngest.info      页数 / 是否加密
  ↓
PdfIngest.text      文本层抽取 + 质量评分
  ├─ 达标 → 文本模式
  └─ 不达标 → PdfIngest.render 逐页 JPEG（最多 4 页）
                → AssetServer /__pdfpage/<hash>_p<n>.jpg
                → 页面 fetch 成 data URL（模型访问不到 127.0.0.1）
  ↓
POST {baseURL}/chat/completions   （用「AI 助手」里已配好的接口/模型）
  ↓
extractContent → extractJson → mapAiResult
  ↓
可编辑预览（逐条改 + 删除 + 待确认标记）
  ↓
覆盖 / 追加 → mergeTimetable → saveMeta('timetable')
```

PDF 全程不出本机：读取、渲染、文本抽取都在 App 内完成；
只有「文本」或「页面图」会发给你自己配置的接口，不经过任何第三方服务。

## 四、关键代码模块

| 模块 | 职责 |
| --- | --- |
| `PdfIngest.java`（新增） | `infoJson` 页数/加密判断；`textJson` 文本抽取与质量评分；`renderJson` 逐页渲染 JPEG 到私有缓存；`clear` 清缓存 |
| `AssetServer.java` | 新增 `/__pdfpage/` 路由，按白名单文件名从缓存目录取图（防目录穿越） |
| `MainActivity.java` | Bridge 新增 `pdfInfo / pdfText / pdfRender / pdfClear`；`pickFileTyped` 支持 MIME 过滤（原 `pickFile` 保留，不影响文件传输） |
| `lib/pdfImport.js`（新增） | 提示词、请求体、响应解包（`extractContent`）、JSON 抽取（`extractJson`）、字段归一化（`mapAiCourse`）、去重、校正后复验（`revalidate`）、导入对象（`toCourse`） |
| `lib/native.js` | `pickPdf / pdfInfo / pdfText / pdfRender / pdfClear / imageToDataUrl`，老 APK 缺桥时返回明确错误而不是静默失败 |

## 五、让模型稳定输出 JSON 的做法

1. **system 里给 schema**，并明确 7 条硬规则：只输出一个 JSON、day 用 1-7、
   一门课多天/多周次拆多条、看不清留空并标 `uncertain`、不要合并或改名。
2. **temperature 0.1**，`stream: false`。
3. **响应先解包再解析**：`extractContent` 处理 `choices[0].message.content`
   与 SSE 的 `data:` 行；`extractJson` 再处理 ```json 围栏、前后解释文字、
   顶层数组、被截断的输出（按括号栈补齐）。
4. **失败不猜**：课程名为空、明显是表头（「星期」「节次」「备注」）的行直接丢弃并计数，
   不生成占位课程。

## 六、待确认与手动校正

每条草稿带 `issues`，分两级：

| 级别 | 触发 | 表现 |
| --- | --- | --- |
| `warn` | 星期/节次/周次缺失或越界；模型自报 `confidence=low` 或 `uncertain` 含该字段 | 行边框变橙 + 行内橙色标签 |
| `info` | 缺地点、缺教师 | 行内灰色标签，不拦导入 |

预览里每个字段都可改：名称、星期、节次起止、周次起止、单双周、地点、教师；
每条可删除（误识别的表头、非本学期的课）。改动后立即重新校验并刷新顶部统计
（`N 条 · M 条待确认`）。仍有 `warn` 时点导入会二次确认，用户可以选择「仍要导入」。

导入前可补「开学日期」，用于计算当前第几周与单双周。

## 七、边界（如实说明）

- **不做 OCR**：扫描件走的是视觉模型，模型看不懂时只能提示，不会硬猜。
- **需要支持图片的模型**：文本模式任何 OpenAI 兼容模型都能用；图片模式需要
  多模态模型（gpt-4o、qwen-vl、glm-4v 等）。不支持时接口通常返 400，
  页面会明确提示换模型或改用「粘贴文字让 AI 识别」。
- **最多渲染 4 页**：课表一般 1-2 页；超过 4 页只识别前 4 页，避免请求体过大。
- **文本抽取是尽力而为**：不解析对象流（ObjStm）里的字体定义、不区分多字体的
  CMap 作用域，少数 PDF 会串字；质量分低时会自动转图片，不会把乱码当课表。
- **周次模型限制**：本 App 一门课只能存一个连续周次段，"2-3,8-17" 会拆成两条；
  预览里会看到两条同名列，这是数据模型决定的，不是重复识别。
- **上限 200 条**，超出截断并提示。
- PDF 与渲染图只存在应用私有缓存，导入结束即清理；不发往任何第三方。

## 八、验证

- 单测 `android/tests/pdf-import.test.mjs` **30 项**：围栏/前后说明/截断 JSON、
  中文星期与节次、多段周次拆分、单双周、表头丢弃、低置信度升级、别名读取、
  去重、上限、响应解包（完整 JSON + SSE）、请求体形状。
- 端到端 `_tools/pdf-ai-check.mjs` **30 项**：入口与配置引导、文本模式请求体、
  图片模式内联 data URL、待确认标记、改名与改星期后导入、二次确认、
  非 JSON 失败提示、空结果、粘贴文字入口、追加导入、缓存清理。
- 原生渲染与文本抽取在浏览器里无法执行，端到端用 mock 顶替；
  Java 侧以 `javac` 全量编译通过作为最低保证，真机需实际选一份 PDF 验证。

## 九、真机验收路径

我的 → 课表 → 导入 → AI 识别 PDF 课表 → 选一份教务导出的 PDF
→（识别中）→ 逐条核对黄色项 → 覆盖导入 / 追加到现有。
