# 15 · 安卓端 AI 历史对话管理（3.3.0）

> 目标：自动保存并展示所有历史对话，可查看 / 继续；支持单条与批量删除（删除前确认）；
> 新建对话不影响已有历史；新对话与历史对话在界面上清晰区分。
> 本文说明数据存储方案、会话切换流程与关键交互细节，并写明取舍边界。

## 1. 改造前的状态

AI 页原来只有一个 `S.meta.aiMessages` 数组（进入页面时 `slice(-60)`），
「+ 新对话」直接把它清空并二次确认「当前记录会清空」，设置面板还有一个语义不同的「清空对话」。
也就是说：**聊天记录只有一份，开新对话 = 丢掉上一份**，没有「历史」这个概念。

## 2. 数据存储方案

### 2.1 结构：IndexedDB `meta` store，按会话分 key

| key | 内容 | 说明 |
| --- | --- | --- |
| `aiSessions` | `[{id,title,createdAt,updatedAt,count,preview}]` | 会话索引，按 `updatedAt` 倒序，轻量，历史列表只读它 |
| `aiChat:<id>` | `[{role,content,tools?}]` | 单个会话的消息体，最多 60 条 |
| `aiActiveId` | `''` 或会话 id | 当前打开的会话；`''` = 尚未发出的新对话草稿 |
| `aiMigrated` | `'1'` | 旧 `aiMessages` 已迁移标记，防止重复建会话 |
| `aiMessages`（旧） | 旧版单数组 | 只用于首次迁移，之后不再写 |

实现文件：`lib/chatStore.js`（纯函数模型） + `lib/core.js` 新增 `applyMeta(writes, deletes)` / `delMeta(key)`。

### 2.2 为什么这样选

- **不升 DB_VER、不新建 object store**。现有库 `DB_VER=2`，只有 `records` / `meta` 两个 store，
  `idbWrite` 也只对这两个开事务。新增 store 要写 `onupgradeneeded` 迁移，
  覆盖安装时一旦迁移失败就是数据事故；用 meta 分 key 是零 schema 变更。
- **每个会话独立 key**，追加一条消息只写「这一个会话」+ 索引，不用把所有历史重写一遍；
  删除用 `metaDel` 真正删掉 key，不留空壳。
- **一次事务原子写**：`applyMeta([[chatKey,id],[aiSessions],[aiActiveId]], [被删的 key...])`
  把消息体、索引、指针放在同一个 IndexedDB 事务里，不会出现「索引说有、消息没了」的中间态。
- **天然不同步到电脑**：`syncNow()` 只推 `S.records` 里的脏记录，`meta` 不在 PROTO 2 载荷内。
  因此对话历史只留在这台手机上 —— 既避免把大量聊天文本推给 PC，
  也避免改动同步协议。这是**有意的取舍**，不是遗漏。
- **代价**：`S.meta` 常驻内存，所以设上限而不是无限增长（见 2.4）。

### 2.3 旧数据迁移（不丢历史）

首次进入 AI 页时 `initStore()` 检查：若 `aiMessages` 非空且 `aiMigrated !== '1'`，
就把它转成一条历史会话（标题取首条提问、时间取当前），并把 `aiActiveId` 指向它 ——
用户升级后打开 AI 看到的还是原来那段对话，不会因为改版「白屏」。
迁移写入用 `applyMeta`，**必须先执行再读消息**（`applyMeta` 同步更新 `S.meta`），
否则首次进入会显示一条空会话（这个顺序问题由端到端用例 `旧 aiMessages 迁移` 覆盖）。
已迁移过则不再重复建；`aiActiveId` 指向已删除会话时自动回到新对话草稿态。

### 2.4 容量与裁剪（不静默丢数据）

- 单会话消息裁剪到 **60 条**（沿用旧行为），只在落盘时裁，保留消息对象引用 ——
  流式回复的回调还指着那个对象，复制会断掉增量更新。
- 历史会话上限 **100 条**。达到上限时新建对话会明确提示「请先删除一些」，
  **不会自动删最旧的**，避免用户数据被悄悄清掉。
- 会话标题取首条用户消息（去换行、截 24 字），之后不再变；
  预览取最后一条有内容的消息（截 40 字）。

## 3. 会话切换流程

状态只有两种：`activeId === ''`（新对话草稿）或 `activeId = 某会话 id`（查看 / 继续中）。

```
进入 AI 页
  └─ initStore(S.meta) → sessions / activeId / 迁移 writes
       ├─ applyMeta(writes)（同步更新 S.meta）
       └─ messages = sessionMessages(S.meta, activeId) 或 []
            └─ render()：状态条 + 消息气泡 + 输入区

点「+ 新对话」
  └─ activeId='' , messages=[] , applyMeta([[aiActiveId,'']])
       └─ 历史会话一条都不动、不需要确认，状态条回到「✦ 新对话」

发送第一条消息（新对话）
  └─ 懒创建 activeId（若已达 100 条则拒绝并提示）
       └─ push 用户消息 + assistant 占位 → persist() 立即落盘
            └─ 请求模型，流式增量只更新内存与 DOM
                 └─ finally：成功 / 失败 / 主动停止都再 persist() 一次
                      └─ 刷新 title / updatedAt / count / preview，索引重排

点「历史 N」→ 面板
  └─ 点某条 → switchSession(id)
       ├─ activeId=id
       ├─ messages = sessionMessages(S.meta,id)（完整消息，可回看）
       ├─ applyMeta([[aiActiveId,id]])
       └─ render() 滚到最新一条 → 之后发消息 = 继续这个会话
            （history 上下文由该会话的 messages 构建，不掺其它会话）

删除单条 / 批量
  └─ confirmAsync(带标题或条数的确认文案)
       └─ 取消 → 什么也不做
       └─ 确认 → applyMeta([[aiSessions,剩余],[aiActiveId,新指针]], [被删的 chatKey...])
            └─ 若删的是当前会话 → 回到新对话草稿态
```

## 4. 关键交互细节

| 细节 | 做法与理由 |
| --- | --- |
| **懒创建** | 新对话只有在真的发出第一条消息时才落库；反复点「+ 新对话」不会堆出一串空会话 |
| **自动保存时机** | 提问 + 占位回复先落盘一次（中途被杀 / 断网也不丢提问），流式结束再落盘完整回复；切换会话不额外写 |
| **新 vs 历史区分** | 顶部状态条：`✦ 新对话 · 发第一条消息后自动保存`（主题色描边） vs `↺ 历史对话 · <标题> · N 条`；空状态引导语也不同；历史面板里当前会话高亮并带「当前」标记 |
| **发送中锁定** | 正在回复时禁止新建 / 切换 / 删除（提示「先停止或等回复结束」），防止流被写进错误的会话；用户可先点「■」停止 |
| **删除确认** | 单条：`删除对话「<标题>」？删除后不可恢复。`；批量：`删除选中的 N 条对话？删除后不可恢复。`；点遮罩 / 取消都不删；确认框层级高于历史面板 |
| **批量删除** | 「批量选择 → 复选框 / 全选 → 删除选中（N）→ 确认」；删完自动退出选择模式 |
| **设置面板语义统一** | 原来的「清空对话」改为「删除当前对话」，走同一套确认与删除逻辑，不再出现「清空了但历史里留空壳」 |
| **模型没配好也能看历史** | 未配置引导页加了「查看历史对话（N）」按钮；换模型 / 清 Key 不会让旧对话消失 |
| **滚动与上下文** | 切到历史会话后滚到最新一条；继续提问时上下文只取该会话的消息，按原逻辑过滤成 user/assistant |
| **面板层级** | `.hist-mask` z-index 45，低于确认框 50、高于底栏 15 |

## 5. 已知边界（如实说明）

- 历史**只在本机**，不随「待办同步」到电脑，也不做云备份；卸载 App / 清除数据会一起消失。
  需要留档时用系统分享或复制文本自行保存 —— 本版没有导出功能。
- 单会话超过 60 条会裁掉最早的消息（与改造前一致），没有「加载更早消息」。
- 会话标题自动生成，本版不支持手动重命名。
- 历史列表按「今天 / 昨天 / 更早」分组，没有搜索 / 按标题筛选。
- 达到 100 条上限后必须手动删除才能继续新建，不会自动清理。
