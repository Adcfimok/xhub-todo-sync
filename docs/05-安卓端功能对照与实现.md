# 安卓端：功能对照与实现（v2.8）

> 目标：把 x-hub 桌面端的**内容与能力**搬到手机上，并且在没有电脑时也能独立使用。
> 本文回答三件事：**搬了哪些、怎么搬的、哪些搬不了以及为什么**。

---

## 1. 功能对照表

| x-hub 桌面功能 | 手机端 | 说明 |
|---|---|---|
| **待办** | ✅ 完整 | 新建 / 编辑 / 勾选 / 删除、分组（逾期·今天·明天·本周·以后·无日期）、优先级、截止时间、备注、筛选 |
| 待办 · 周期规则 | ⚠️ 只读 | 显示「周期」标记；规则编辑只保留在桌面（宿主 `todo_recurrence.rs` 是唯一实现，手机端重写必然漂移） |
| 待办 · 标签 | ❌ 暂无 | 桥接口存在（`todoTags`），移动端 UI 成本高、收益低，留待下一版 |
| **笔记** | ✅ 完整 | 列表、全文搜索、标题+正文编辑、删除 |
| 笔记 · 文件夹 | ⚠️ 平铺 | 桥没有文件夹接口，全部平铺；`folderId` 字段随记录同步，不丢 |
| 笔记 · 回收站 | ⚠️ 只读 | 删除即同步删除（墓碑），不提供恢复 |
| **便签** | ✅ 完整 | 两个槽位，输入防抖 0.7s 自动保存 |
| **速达** | ✅ 打开网页 | 网页类可直接跳系统浏览器；`app` / `file` 类型仅展示（手机上没有对应程序） |
| **提示词** | ✅ 完整 | 列表、搜索、一键复制、置顶 |
| **倒计时** | ❌ | 宿主侧没有数据接口（纯 UI 组件），无法跨端取数 |
| **日历** | ❌ | 依赖周期展开接口（`expandOccurrences`），移动端日程视图留待下一版 |
| **AI 助手** | ✅ | 任意 OpenAI 兼容接口；手机存密钥，请求经电脑中转；流式输出 |
| **扩展** | ✅ 运行 `view` 页面 | 电脑托管静态资源，手机 iframe 渲染，注入桥垫片；`data.*` 由电脑页面代答 |
| **设置** | ⚠️ 部分 | 主题（跟随/浅/深）、同步参数、设备管理、冲突处理 |
| 壁纸 / 字号 / 快捷键 | ❌ | 桌面形态专属，手机上无对应概念 |
| 剪贴板历史 | ❌ | 依赖系统级剪贴板监听（Windows 消息 + 常驻进程），Android 沙箱做不到等价能力 |
| 系统监控 | ❌ | 读取的是 PC 的 CPU/内存/磁盘，手机上无意义 |
| 悬浮球 / 钉图 / 录音 / 独立浮窗 / 托盘 | ❌ | Windows 窗口体系能力，Android 无对等物 |
| 全局搜索 | ⚠️ 分页内搜索 | 各页独立搜索；未做跨类型聚合搜索 |

**结论**：桌面端的**全部数据类内容**（待办 / 笔记 / 便签 / 速达 / 提示词）已经双向同步并可在手机上原生编辑；
**AI 与扩展**两条能力链已打通；剩下的都是「桌面形态专属」或「宿主没有数据接口」的功能，不是没做，是做不了等价物。

## 2. 架构

```
Android WebView (assets/www)
├─ app.js                路由 + 底部导航 + 返回键
├─ lib/core.js           IndexedDB / HLC / 状态 / 同步引擎 / HTTP
├─ lib/ui.js             DOM 构造、表单面板、确认框、日期格式化
├─ lib/cal.js            日历数据层（日期键 / 月排布 / 按天聚合 / 日期格）
├─ lib/todoform.js       待办编辑面板（待办页与日历页共用）
├─ lib/platform.js       x-hub 平台客户端（账号/邀请码/开发者/平台 AI）
├─ lib/native.js         原生桥封装（出站 HTTP / 通知 / 剪贴板 / 外链）
├─ lib/alerts.js         全局提醒调度（待办临期 + 番茄钟到点）
├─ lib/agent.js          AI 工具定义 + agent 循环（list/create/update/delete_todo）
└─ pages/
   ├─ home.js            首页概览（含日历入口卡片）
   ├─ calendar.js        日历月视图
   ├─ account.js         账号与邀请码（登录/兑换/开发者/设备）
   ├─ pomodoro.js        番茄钟（扩展页内置工具入口）
   ├─ todos.js           待办
   ├─ notes.js           笔记
   ├─ stickies.js        便签
   ├─ resources.js       速达
   ├─ snippets.js        提示词
   ├─ ai.js              AI 对话
   ├─ ext.js             扩展宿主
   ├─ more.js            我的（二级入口）
   └─ settings.js        同步与设置
```

- **子页面**：`location.hash` 路由。底栏是酷安式结构：**首页 / 待办 / 笔记 / ＋ / AI / 我的**，
  5 个页面格 + 1 个动作格。二级页按来源回退：日历回首页，便签/速达/提示词/扩展/设置/账号回「我的」；
  安卓物理返回键先关面板、再退子页、最后才退出。
- **页面契约**：每个页面导出 `{ meta:{title,route}, mount(root) → cleanup }`，切换时自动卸载订阅。
- **数据层**：所有页面只经 `lib/core.js` 读写，页面不知道网络存在。

## 3. 同步层（从「只同步待办」升级为「多集合」）

| 项 | v1 | v2 |
|---|---|---|
| 记录 id | `h:12` / `a:xxx` | `todos:h12` / `notes:a3f…`（前缀即集合） |
| 协议版本 | `proto:1` | `proto:2` |
| 宿主入库 | `/api/local/ingest`（隐式 todo） | 显式 `{col, records, full}`，五类并列 |
| 回写 | 只有 todo 适配器 | 五个适配器（todos / notes / stickies / resources / snippets） |
| 拉取 | 全量 | `cols` 过滤，手机只订五类 |
| 冲突 | todo 专用字段表 | 按集合定义字段表（`FIELDS`） |

同步语义不变：**HLC + 记录级 LWW + 墓碑 + 增量游标**，冲突可回溯、可恢复。

## 4. AI 链路

```
手机 AI 页  ──POST /api/ai/chat（Bearer 令牌）──▶  电脑端中枢
                                                    │  带着手机的 key 转发
                                                    ▼
                                       任意 OpenAI 兼容 /chat/completions
```

- **密钥只存在手机本地**（IndexedDB 的 meta），电脑只在内存里周转，不落盘、不打日志。
- 电脑中转的原因：手机 WebView 直连外部 API 会遇到 CORS 与证书问题；Node 侧没有这些限制。
- 流式：电脑把上游 SSE **原样透传**给手机，手机逐块解析 `delta.content`，边收边渲染。
- 未配对时 AI 页明确提示先配对——这是设计约束，不是缺陷：中转必须有一个已知的电脑地址。

## 5. 扩展宿主（手机运行 x-hub 扩展）

```
手机 iframe  ──GET /ext/r/<token>/<extId>/view/index.html──▶ 电脑中枢
                                                              │ 读磁盘上的扩展目录
                                                              │ 注入 <base> + 桥垫片
                                                              ▼
                                              扩展页面（原样，含它自己的 CSS/JS）
                                                     │ window.xhub.*
                                                     ▼
                            中枢桥接信箱 ◀──轮询── 电脑端「待办同步」整页（有真桥）
```

关键决定：

1. **令牌放进 URL 路径**（`/ext/r/<token>/<id>/…`）：iframe 里的 `<link>`、`<script>`、`fetch` 都会自动继承前缀，
   不需要给每个子资源加请求头，也不会掉进第三方 Cookie 被拦的坑。
2. **`<base>` 指向被请求文件所在目录**（不是扩展根）：`view/index.html` 里的 `./view.css` 才能正确解析。
3. **桥垫片**：注入 `window.xhub`，把 `storage` / `config` 落到中枢的 KV，把 `data.*` 转成桥接请求。
4. **`data.*` 由电脑页面代答**：中枢没有宿主数据库的访问权，真正能读数据的是 x-hub 里的整页。
   电脑页面没开时，垫片返回「电脑端页面未打开」，扩展自己会渲染错误态（已验证：待办倒计时扩展会显示这条提示并可重试）。
5. **`service.request` 在手机端不可用**：每个 service 扩展的后端是独立进程、端口由宿主动态分配，中枢无从得知。
   垫片直接拒绝并给出原因，避免扩展拿到 404 后瞎猜。

实测：把 `todo-countdown 1.1.0` 放进扩展目录，手机端打开后**样式完整、读到真实待办**（逾期/今天/临期三档、倒计时天数都正确）。

## 6. 本地存储与离线

- IndexedDB：`records`（按 `id` 主键）+ `meta`（设备 id、令牌、游标、AI 配置、主题）。
- 所有写入先落本地、标 `dirty`，再异步推送；断网时完全不影响使用。
- 冷启动先渲染本地数据（毫秒级），再后台拉增量——不阻塞首屏。

## 7. 日历（首页卡片 + 月历页）

**入口**：首页中部一张「日历」卡片，展示本月缩略月历；点卡片进日历页（整卡一个入口），点某个日期格则带着那一天进日历页。

**月历表格**

- 周一为一周起始，`一二三四五六日` 表头，前后月的补白日期弱化显示、可点按跳月。
- 每个日期格最多 3 个圆点表示当天的待办：**红点＝有逾期未完成，灰点＝当天全部完成，紫点＝正常未完成**；超过 3 条不再堆点（详情在下方面板）。
- 今天用主题色实底高亮，选中日用描边圈住，两者可同时出现、互不混淆。

**当日面板**：月份下固定跟着「× 月 × 日 · 周× · N 件」，列出当天待办（时间、优先级、待同步标记），
点行编辑、点方框直接勾选完成，右下角 `+` 新建会自动带上这一天。

**无日期兜底**：没有截止日的待办不在任何格子里，底部给「另有 N 条待办没有日期 · 去待办」入口，不留死角。

**与待办共用数据**：日历不另存数据，直接读 `colRecords('todos')` 的 `dueAt`；
新增/编辑走共享面板 `lib/todoform.js`，与待办页同一条校验、同一套时间戳保留逻辑，避免两处漂移。

**适配原则**：格子尺寸靠「容器内的类名」区分——首页卡片格子 22px、日历页格子 42px，圆点与字号同步放大，
日期排布、按天聚合、圆点取色全部收敛在 `lib/cal.js`，两处不复制粘贴。

## 8. 账号与平台 AI（v2.2）

**平台服务端**：`https://x-hub.xfactor.top`。与局域网同步无关——账号是云端服务，手机 WebView 直接 fetch
（服务端已放开 CORS：`access-control-allow-origin: *`，预检也通过，无需原生桥）。

**账号中心**（「我的 → 账号与邀请码」）

- 登录：邮箱验证码（国内兜底）+ GitHub 设备码；token 存 `meta.ptToken`，与电脑配对 token（`meta.token`）严格分离。
- 兑换邀请码：`POST /api/v1/me/redeem`，账号与权益解耦——兑换后才发额度、才可申请开发者。
- 开发者申请：`POST /api/v1/dev/apply`，状态 none/pending/approved/rejected。
- 我的设备：`/api/v1/me/device-tokens` 列表 + 单台撤销（本机只能退出登录，不能撤销自己）。
- 额度展示：`/me` 返回 `quota` / `credits` / `invite_redeemed` / `developer_status`。

**内置 AI 配置**（AI 页 ⚙）

- 供应商预设与桌面端 `PRESET_FALLBACK` 逐项对齐：DeepSeek / OpenAI / Moonshot 月之暗面 / 阿里云百炼 /
  Ollama（本机），各带 `baseUrl`、`keyGuideUrl`、`note`；登录后可用平台可配清单覆盖（`/api/v1/ai/provider-presets`）。
- 「获取 xxx API Key」链接沿用桌面端文案与 `ExternalLink` 图标；**点击走系统浏览器**（原生 `Intent.ACTION_VIEW`），
  与桌面端 `openExternal` 同义——WebView 内 `window.open` / `target=_blank` 出不去，宿主只放行本机资源。
  `keyGuideUrl` 为空时（如 Ollama）整条链接不渲染，与桌面端 `v-if="p.keyGuide"` 一致。
- 平台免费额度：开关开启后 baseURL 锁定平台 `/v1`、Key 用账号登录态、模型从 `/api/v1/ai/models` 拉取，
  对话**直连平台公网**（不经过电脑）。自备 Key 仍走电脑中转、密钥只存手机。

**边界**：平台额度依赖登录；未登录时开关给出「先去账号页登录」的就地提示，不报错、不卡死。

## 9. 脱离电脑与本地能力（v2.3）

**AI 直连（关键变化）**

v2.2 及以前，自备 Key 的请求要经电脑 `/api/ai/chat` 中转。现在手机自己发：

- 原生桥 `httpStream(reqId, method, url, headers, body)` 用 `HttpURLConnection` 发请求，
  逐块回 `window.__httpChunk / __httpDone / __httpError`，JS 侧包装成 `streamHttp()`。
- 为什么必须走原生：供应商 API 基本不给浏览器放开 CORS，WebView 从 `http://127.0.0.1` 发出去会被预检拦掉。
  原生请求没有这个限制，AI 才能真正脱机。
- 交互：**未配对电脑也能完整对话**（实测 `paired:false` 下流式返回正常）。

**两个诊断对话框**（AI 页 ⚙）

| 按钮 | 做什么 | 成功反馈 |
|---|---|---|
| 测试连通 | 发一次 `max_tokens:1` 的真实对话，同时验地址 / Key / 模型名 | 「连通正常 · 模型名 · 32 ms」 |
| 获取模型 | `GET {baseURL}/models`，弹层列出 `data[].id` 供点选 | 选中即回填模型名 |

**待办临期通知**

- 原生 `notify(title, body)`：Android 8+ 建 `xhub_reminder` 渠道，13+ 动态申请 `POST_NOTIFICATIONS`。
- 调度在 `lib/alerts.js`：每 30 秒扫一次 + 数据变化后防抖扫 + 回到前台立刻扫。
- 规则：到期前 15 分钟提醒；过期 1 分钟内补一次；按 `记录 id + 截止时间` 去重，同一条不会重复弹。
- 设置里可整体关闭（`notifyTodo`）。

**番茄钟**（扩展页 →「内置工具」）

25 分钟专注 / 5 分钟休息，`endAt` 存绝对时间戳，切页、退到后台都不影响计时；
到点发通知 + 震动并自动切到另一模式。页面内 250ms 刷新表盘，到点判定与通知走全局 `sweep`，离开页面也能响。

**主题**

- 三档模式：浅色 / 深色 / 跟随系统（跟随系统时监听 `prefers-color-scheme` 实时切换）。
- 六种主题色：靛紫 / 海蓝 / 青碧 / 森绿 / 暖橙 / 樱粉，深色与浅色各一套取值（浅色下压暗保证对比度）。

**剪贴板**

- 原生 `readClipboard()` / `writeClipboard(text)`，浏览器预览降级到 `navigator.clipboard`。
- 待办新建面板的「标题」右侧有「粘贴」，一键带入剪贴板文本；提示词复制、出品方微信号复制也走同一条通道。

**底栏（v2.4 增强）**

- 玻璃质感分四层：`backdrop-filter: blur(22px) saturate(190%)` 背景模糊 → 半透明底 →
  `::before` 上缘渐变高光 → `::after` 内描边；盒阴影用「外部上投影 + 顶部 1px 高光 + 底部内阴影」三层叠加。
- 高亮块是独立一层：渐变底 + 1px 描边 + 内高光 + 外投影。
- **跟手滑动**：在底栏上拖动时，`--drag` 逐帧写入像素偏移，`transform` 合成
  `calc(var(--tab-i) * 100% + var(--drag))`；拖拽期间加 `.dragging` 关掉过渡，保证与手指同帧。
  两端带阻尼（越界只走 32%），松手按 `round(位移 / tab 宽)` 吸附到最近 tab 并切页。
- 只挂 `transform` 与 CSS 变量，走合成层（`will-change: transform`），不触发布局重排。

## 10. AI 助手接入待办（v2.4）

**工具集**（对齐桌面端 `src-tauri/src/agent/builtin.rs`）

| 工具 | 参数 | 行为 |
|---|---|---|
| `list_todos` | — | 按 置顶/逾期/今天/有日期/无日期 分组返回未完成项，每行带 `[编号]` |
| `create_todo` | title / due_at / priority / description | 建待办；`due_at` 支持「YYYY-MM-DD HH:mm」或毫秒 |
| `update_todo` | todo_id / title / due_at / priority / done | 字段缺省即不动，`due_at: null` 表示清除 |
| `delete_todo` | todo_id | **执行前弹确认**；用户拒绝则把「已取消删除」回传给模型 |

**agent 循环**（`lib/agent.js::runAgent`）

1. 请求带 `tools`，流式解析 `delta.content` 与分片的 `delta.tool_calls`（按 index 累积 id/name/arguments）。
2. 有工具调用 → 落一条 `assistant(tool_calls)` 消息 → 逐个执行 → 追加 `role:"tool"` 结果 → 再请求。
3. 没有工具调用即收尾；最多 6 轮，**末轮不下发 tools**，逼模型收口（同桌面端做法）。
4. 系统提示词注入当前时间，并保留桌面端的三条铁律：判断要不要查 / 写操作必须真调用工具（禁止谎报）/ 删除要先确认。

**编号解析**：`todo_id` 可以是完整 id、`h12` 形式、宿主数字 id，或标题片段——标题命中多条时把候选抛回模型，
而不是猜一个（对应桌面端 `resolve_by_id` 的语义）。

**界面**

- 顶部工具条：模型名 / ⚙ / **+ 新对话**（有记录时二次确认）。
- 底部**磨砂胶囊输入区**：`backdrop-filter: blur(20px)`，圆角 26px；框内顶部一行显示
  `↑ 输入 · ↓ 输出 · 缓存 N（x%）· N tok/s`，数据取自流式响应末尾的 `usage`（含 `prompt_tokens_details.cached_tokens`）。
- 等待回复时气泡里是**三点上下跳动**（`@keyframes bump`，三个点分别延迟 0/140/280ms）；
  工具执行完但正文未出时三点继续转，工具结果以绿色徽章挂在气泡下方。
- 局部刷新：正文增量与工具徽章都走 DOM 局部更新，不整页重绘，输入框不会失焦。

## 11. 待办卡片：内容自适应（v2.5）

**要解决的问题**：早期卡片是固定视觉高度 + 描述两行截断，长标题挤成一条、长备注被切掉，
在窄屏上更明显。现在改成「内容说多高，卡片就多高」。

**三层机制**

| 层 | 做法 | 效果 |
|---|---|---|
| 分组容器 | `grid-template-columns: repeat(auto-fill, minmax(min(100%, 272px), 1fr))` + `align-items: start` | 窄屏 1 列、平板自动 2–3 列；每张卡只占自身高度，不被同行最高卡拉齐 |
| 卡片 | `height: auto`、`min-height: 0`、`padding: clamp(11px, 3.2vw, 15px)` | 高度随标题/描述增长；内边距随屏宽轻微缩放 |
| 文本 | 标题 `white-space: pre-wrap` + `overflow-wrap: anywhere`；描述**删掉 `-webkit-line-clamp`** | 中文、长英文串、无空格长链接都能断行，不溢出、不省略 |

**其他调整**

- 卡片改 `grid-template-columns: auto minmax(0, 1fr)`，正文列可被压缩，长内容不会把卡片撑出屏幕。
- 元信息（时间 / 优先级 / 待同步 / 周期）改 `flex-wrap: wrap`，放不下换行而不是挤压标题。
- 优先级从正文里的 chip 之外再加一条左侧竖条（`::before`），不占正文宽度、不影响高度。
- 描述用 `white-space: pre-wrap` 保留换行，并与元信息之间加虚线分隔，长备注仍然可读。
- 首页与日历里的紧凑待办行同步去掉 `text-overflow: ellipsis`，长标题换行、行高随之增长。

**实测（Edge，多屏宽）**

| 宽 | 列数 | 卡片高度范围 | 截断 | 横向溢出 |
|---|---|---|---|---|
| 320 | 1 | 69–1069px（含 3000 字备注压力用例） | 无 | 无 |
| 360 / 390 / 430 | 1 | 70–270 / 73–234 / 77–221px | 无 | 无 |
| 768 | 2 | 79–247px | 无 | 无 |
| 1024 | 3 | 79–288px | 无 | 无 |

判定口径不是「看起来没切」：逐卡比较 `scrollHeight` 与 `clientHeight`，并用
`scrollWidth / clientWidth` 检查横向溢出，全部通过。

## 12. 底部导航：酷安式悬浮胶囊（v2.7）

**结构**：5 个页面格 + 1 个动作格，共 6 格。

| 位置 | 内容 | 说明 |
|---|---|---|
| 0 / 1 / 2 | 首页 / 待办 / 笔记 | 页面 |
| 3 | ⊕ 新建 | 动作，不参与切页，也不参与高亮 |
| 4 / 5 | AI / 我的 | 页面 |

**关于 ⊕ 的位置**：酷安原版是 4 页 + 中央 ⊕（正好居中）。这里是 5 页 + 1 个动作，6 格均分，
⊕ 落在第 4 格、比几何中心偏右约 30px（390 宽）。要严格居中只能砍掉一个页面，或把某侧 Tab 拉宽到 75px /
另一侧压到 50px——两个方案都比「略偏右」更难看，所以选了等宽 + 靠右半格。
拖动吸附时会跳过第 3 格，不会停在动作格上。

**几何与玻璃**

- 悬浮：`left/right: 8px`、**`bottom: 22px` + 安全区**（v2.7 从 8 上移到 22，落进拇指自然弧线），
  高 **58**、圆角 **29**（正圆角胶囊）。
- 材质四层：`backdrop-filter: blur(24px) saturate(190%)` → 半透明底 → `::before` 上缘渐变高光 →
  `::after` 内描边；盒阴影三层（`0 14px 32px` 外投影 + `0 2px 8px` 近距 + 顶部 1px 内高光）。
- 选中态是一枚 **48 高的药丸**：浅色下纯白 `#fff` + `rgba(20,24,40,.08)` 描边，深色下 `rgba(255,255,255,.16)`。
- 图标 23px 实底字形、标签 10.5px（六格比五格窄，字号收 0.5px）；选中变主题色并加粗。
- 中央 ⊕ 是 **54×42 / 圆角 15** 的方块，主题色 + 顶部白色高光渐变 + 外发光，按下 `scale(.93)`。

**为什么悬浮**：只有浮在内容之上，滚动时卡片才会从玻璃背后经过，模糊才有东西可糊。
贴底的玻璃栏永远只糊到页面背景色，看起来就是一块纯色板。

**跟手滑动**

- 拖动时把像素位移写入 `--drag`，`transform: translateX(calc(var(--tab-i) * 100% + var(--drag)))`；
  拖拽期间加 `.dragging` 把过渡设为 `0s`，与手指同帧。
- 两端阻尼 32%；松手按 `round(位移 / 格宽)` 吸附，**吸附只在 0/1/2/4/5 五个页面格里选最近的**。
  从笔记(2) 往右拖一格，目标是 3，与 2、4 等距——此时按拖动方向倒向 4，
  否则会出现「拖了一格又弹回原位」。
- 只改 `transform` 与 CSS 变量，走合成层，不触发布局重排；`prefers-reduced-motion` 下关闭过渡。

**中央 ＋ 的含义跟着页面走**（`lib/quickadd.js`）

| 页面 | ＋ 的动作 |
|---|---|
| 首页 / 待办 / AI / 我的 / 设置等 | 新建待办（默认回落） |
| 笔记 | 新建笔记 |
| 速达 | 新增速达条目 |
| 提示词 | 新增提示词 |
| 日历 | 按当前选中日期新建待办 |

机制：页面 `mount` 时 `setQuickAdd(fn)` 注册，路由切换前 `resetQuickAdd()` 清空，
没有注册就回落到新建待办。原先各页右下角的 FAB 已移除，全应用只剩这一个加号。

**层级**：胶囊 `z-index: 15`，低于面板(20/21)、扫码(30)、提示(40)、弹窗(50)、扩展全屏(60)。
浮在内容上但不遮挡任何浮层——面板打开时胶囊被完全盖住。

**布局让位**：列表尾部留白 122px；AI 输入区 `margin-bottom: 92px`；滚动到底时最后一条内容在胶囊上方约 40px。

## 13. 配对（v2.8）

手机连同一个 Wi-Fi 却始终配对失败，根因在「地址」不在「网络」。v2.8 把配对做成「先给候选，再逐个试」：

| 环节 | 做法 | 文件 |
|---|---|---|
| 扫码 | 支持 `xhub://3/<code>/<ip:port,…>`（多候选，最多 4 个物理网卡）、兼容 v2/v1 单地址 | `lib/paircode.js` → `parsePairPayload()` |
| 探测 | 手输地址优先，其后依次试二维码带来的候选；每个地址 `ping`（6s 超时）→ `pair` | `pages/settings.js` |
| 反馈 | 按钮显示 `连接中… (2/4)`；配对码错 / 次数超限 / 设备满 为终态，立即停 | 同上 |
| 记忆 | 配对成功写入 `host`/`token`/`hubId`/`proto`，并立即 `pullSnapshot()` + 一次 `syncNow('pair')` | `lib/core.js` → `pair()` |

配套的 PC 侧要点（见 `04` 文档 §15）：主地址必须取默认路由网卡，不能按网段猜 —— 开发机上的 VMware / VPN 虚拟网卡
同样落在私网段，猜出来的地址手机根本路由不到。

```bash
# 手机端解析自测
node _tools/paircode-test.mjs     # v1/v2/v3、缺端口、非法载荷
```


## 14. 已知限制

| # | 限制 | 影响 | 处理 |
|---|---|---|---|
| 1 | 扩展的 `data.*` 需要电脑页面在线 | 电脑页面关着时扩展显示错误态 | 提示文案明确；开「常驻后台」即可 |
| 2 | 扩展的 Node 后端不可用 | service 扩展只能跑前端 | 垫片明确拒绝，扩展可自行降级 |
| 3 | 笔记文件夹平铺 | 文件夹结构在手机上不可见 | 数据不丢，桌面端仍按文件夹展示 |
| 4 | 速达的 app/file 类型打不开 | 只能看不能启 | 明确提示「只能在电脑上打开」 |
| 5 | 周期规则不可编辑 | 手机上只能看到「周期」标记 | 规则唯一实现在宿主，避免两套语义 |
| 6 | 设备上限 8 台 | 第 9 台配对失败 | 电脑端可移除旧设备 |
| 7 | 明文 HTTP | 同网段可见内容 | 仅可信网络；令牌准入 |
