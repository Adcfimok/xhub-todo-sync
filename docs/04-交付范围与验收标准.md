## 2. 范围

### 2.1 本次包含

**扩展（PC 端）**

- `module` 工作台卡片：待完成 / 今日到期 / 待回写 三指标 + 最近待办 + 连接状态，2 种形态（紧凑 / 标准）。
- `view` 管理页：配对二维码与 6 位码、局域网地址列表、设备管理（在线状态 / 移除）、待办列表、冲突记录与「恢复被覆盖版本」。
- service 后端：局域网 HTTP 服务（`0.0.0.0:47821`）、配对鉴权、增量同步、SSE 推送、宿主待办桥接。
- 冲突日志与一键恢复。

**安卓端**

- 待办列表（按逾期/今天/明天/本周/以后/无日期分组）、筛选（待办/今天/已完成）。
- 新建 / 编辑 / 勾选 / 删除；标题、截止日期时间、优先级、备注。
- 本地优先存储（IndexedDB），断网全功能可用。
- 配对（手输地址+码 / 扫码）、手动同步、冲突记录、解除配对。
- 完全离线启动不依赖 PC。

**协议**

- HTTP/1.1 + JSON，Bearer 令牌，SSE 推送，HLC + 记录级 LWW，墓碑删除，退避重连。

### 2.2 本次不包含（明确边界）

| 项 | 原因 | 影响 |
|---|---|---|
| 公网 / 跨网同步 | 只监听局域网，不做穿透 | 异地使用需自建 VPN |
| 传输加密（TLS） | 局域网自签证书体验差 | 同网段抓包可见内容，已在界面与文档说明 |
| 字段级合并 | 宿主 `update` 是全量覆盖，无 base 版本可做三方合并 | 冲突按整条记录取舍，可回溯、可恢复 |
| 子待办层级的跨端调整 | 桥 API 不支持改 `parentId` | 手机新建子待办会带上父级；已有条目改父级不支持 |
| 周期待办规则编辑 | 规则语义只在宿主实现（`todo_recurrence.rs`） | 手机端只同步 `repeatMode` 字段，不改规则细节 |
| 提醒推送 | 安卓端未做通知调度 | 手机不响铃，仅界面显示 |
| 附件 / 图片 | 数据模型只有文本 | — |
| 多用户 / 多账户 | 单机单用户场景 | — |

## 4. 部署与使用

### 4.1 扩展

1. 解压 `dist/com.zhou.todo-relay-2.1.0.zip`（或直接指向 `extensions/todo-relay` 源码目录）。
2. x-hub → 扩展中心 →「我的扩展」→ 添加该目录（须含 `manifest.json`）。
3. 首次打开会请求授权：`data:read` / `data:write`（读写待办）、`network`（对外监听 47821）、`notify`（冲突提醒）。
4. 打开整页，记下地址与配对码。

> **重要**：宿主待办与中枢之间的搬运由整页前端完成。页面关闭后，局域网服务仍在跑（手机能连、能收发），
> 但**不会写回宿主待办**。若希望关闭页面也能回写，请在扩展设置里开启「常驻后台」（需 x-hub 0.9.4+）。
> 这是宿主机制决定的，不是本扩展可以绕过的。

### 4.2 安卓端

1. 安装 `android/todo-link-2.8.0.apk`（允许「安装未知来源应用」）。
2. 底部「同步」→ 输入 PC 显示的地址（如 `192.168.1.10:47821`）与 6 位配对码，或点「扫码配对」扫 PC 上的二维码。
3. 配对成功后回「待办」页即可使用；断网也能用。

### 4.3 端口与防火墙

- 固定端口 **47821**。宿主的 service 运行时会自动添加 Windows 防火墙入站规则（TCP、专用网络）。
- 若被安全软件拦截，手动放行 `node.exe` 的 TCP 47821。
- 手机与电脑必须在**同一网段**；公司网络若开启了 AP 隔离（客户端隔离），手机连不上，需换热点或家用路由。

## 5. 已知限制与风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 页面关闭后宿主不同步 | PC 待办滞后 | 开「常驻后台」；或同步前打开扩展页 |
| R2 | 固定端口被占用 | 后端启动失败 | 改 `manifest.backend.port` 后重启后端；日志在 `data/logs/service/<id>.log` |
| R3 | 手机时钟严重偏差 | LWW 判定偏向时钟快的一方 | HLC 已吸收偏差，但物理时间仍是排序主键；建议开启系统自动对时 |
| R4 | 明文 HTTP | 同网段可见内容 | 仅在可信网络使用；文档与界面均已提示 |
| R5 | 宿主 `todos.update` 全量覆盖 | 极小概率覆盖并发写 | 前端逐字段比对后只发必要调用；`expectedVersion` 冲突时重读重试一次 |
| R6 | 安卓 WebView 版本过旧 | `IndexedDB`/`fetch` 行为差异 | 目标 Chrome 90+（Android 8+ 一般满足）；不支持 `color-mix` 等新语法 |
| R7 | 大数量首次同步 | 首屏等待 | 快照分页上限 500，UI 显示进度；实测 5,000 条约 1.2s |

## 6. 自检结论

| 检查项 | 结果 |
|---|---|
| 空值处理 | 宿主字段缺失一律回落到上一条记录或默认值；脏数据单条丢弃不拖垮整卡 |
| 安全 | 令牌只存 sha256；未鉴权接口仅 `ping`/`healthz`；本机接口校验回环来源；无硬编码密钥 |
| 错误处理 | 所有网络失败有明确状态与退避；错误码表见协议文档 §5.7 |
| 状态机 | 同步状态 6 态互斥，终态可回到 offline；设备吊销后不可复用令牌 |
| 并发 | 单进程单线程合并，无锁竞争；重复推送幂等（同 HLC 直接忽略） |
| 性能 | 增量 + 分页；变更日志上限 2,000 条，超出要求重同步 |
| 可回滚 | 扩展为独立目录，移除即卸载；APK 卸载即清除本地数据 |
| 配置 | 端口/间隔/墓碑天数均在 `manifest.config` 或环境变量，无散落魔数 |

## 15. v2.8 增量验收（同局域网配对失败修复 + 读取权限）

### 15.1 复现与根因

现场条件：PC 与手机连同一个 Wi-Fi，扩展页显示「服务就绪」，手机扫码/手输地址后一直转圈，最后报超时；重装、重启后端都无效。

宿主日志是最直接的证据 —— 旧版后端启动时按网卡枚举顺序把 VPN 地址排在了第一位：

```
----- service 启动 2026-11-05 17:43:15 -----
[todo-relay] listening on 0.0.0.0:47821 (proto 2)
[todo-relay] lan: 172.30.238.207:47821, 10.32.3.57:47821, 192.168.21.1:47821, 192.168.128.1:47821
```

`172.30.238.207` 是 VPN 的 `vgate0`，`192.168.21.1` 是 VMware VMnet1 —— 三者都在私网段，手机一个都路由不到。

逐层排查后确认是**五个独立缺陷叠加**，任一存在都会让配对表现为「永远连不上」：

| # | 缺陷 | 现象 | 根因 |
|---|---|---|---|
| C1 | 主地址按 IP 段猜 | 二维码/复制出来的地址是 `192.168.21.1` | 开发机同时有 WLAN、VMware VMnet1/VMnet8、VPN `vgate0`，它们都落在私网段；旧逻辑取第一个私网地址，正好是虚拟网卡 |
| C2 | 二维码只带一个地址 | 扫到的就是 C1 里那个错地址 | 载荷 v2 只有 `host:port` 一个字段，手机没有第二个可试的 |
| C3 | 手机只试一次 | 第一个地址超时就整单失败 | 配对流程是单地址 `await`，没有候选列表与逐个探测 |
| C4 | 后端可能只监听回环 | `127.0.0.1:47821` 通、`10.x.x.x:47821` 不通 | `network` 权限未开启时监听地址回退到 localhost，页面却仍显示「就绪」 |
| C5 | 权限被关时只有一行错 | 五类数据一条都读不到，界面无解释 | 宿主拒绝 `data.*.list` 抛 `PERMISSION_DENIED`，前端只写了 `lastError`，没有给可操作入口 |

另外排查中发现一个会**误删数据**的隐患：宿主页面刚载入或某一类读失败时会送来 `rows=[]`，旧逻辑把空快照当成「宿主全删了」，给该类所有记录打墓碑 —— 这正是此前「笔记莫名消失」的来源。

### 15.2 修复

| 层 | 改动 | 文件 |
|---|---|---|
| 选地址 | 新增 `netinfo.js`：UDP socket 对 `223.5.5.5:53` 做 `connect`（不发包）拿到默认路由出口地址；`rankAddresses()` 以「默认路由 1000 分 / 物理网卡 +100 / 虚拟网卡 -100」排序，过滤 `169.254.*` | `service/netinfo.js` |
| 可诊断 | `/api/v1/diag` 返回 `primary`、`defaultRoute`、每张网卡的 `virtual/rank` 与一句 `verdict`；启动日志同时打印全部候选地址 | `service/index.js` |
| 界面 | 主地址旁标「默认路由 / WLAN」；虚拟网卡灰显 + 「虚拟」徽章；主地址落在虚拟网卡或只监听回环时出红条并给出处理动作 | `view/app.js`、`view/view.css` |

### 15.3 读取范围、授权方式与异常处理

| 项 | 说明 |
|---|---|
| 读取范围 | `data.todos.list` / `data.notes.list` / `data.resources.list` / `data.snippets.list` / `data.stickies.list` —— 只读字段：标题、正文、完成态、优先级、截止/提醒时间、置顶、分类、排序；**不读**账号令牌、AI 密钥、密码类字段 |
