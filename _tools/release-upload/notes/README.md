# 版本说明文件

每个要发布的版本放一个 Markdown 文件，文件名固定为 `<kind>-<version>.md`：

| 产物类型 | kind | 文件名示例 |
| --- | --- | --- |
| x-hub 扩展分发包 | `xhub-extension` | `xhub-extension-2.1.0.md` |
| 安卓安装包 | `android-apk` | `android-apk-2.8.0.md` |

`upload.mjs` 发布时会把这个文件的内容直接作为 Release 正文。文件缺失时不会挡住发布，
但正文会退化成「仅含产物事实」的兜底版本，并在开头注明缺少说明文件——这样不会编造变更内容。

## 写什么

- 本版解决了什么问题（用户视角，一句能听懂的话）
- 具体改了什么（分条，可核对）
- 升级方式、是否保留数据、签名是否变化
- 已知限制
- 校验方式（命令，可复制执行）

## 不要写

- 未经验证的推断、内部代号、占位符
- 会随重建失效的硬编码校验和（用 `verify.mjs` 输出或资产页信息代替）
- 与本次产物无关的路线图

## 校验

```bash
node _tools/release-upload/verify.mjs --offline   # 检查清单、说明文件、标签是否齐备
```
