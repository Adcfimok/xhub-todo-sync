## 本版变更

只有一项：**修复 AI 助手「只聊天、不建待办」**。

先说现象：手机上对助手说「明天下午三点提醒我交房租」，它回一段话，但待办列表里什么都没有；换成电脑端同一个模型、同一句话，待办能正常建出来。

原因不在模型，在手机端的流式解析。

手机端 AI 的响应是 `lib/agent.js` 自己解析的（桌面端走 Rust 侧实现，是另一套代码，所以同场景正常）。这段解析原来有三处硬伤：

1. 只按 `\n\n` 切分事件。经 Cloudflare 或多数中转网关后，分隔符会变成 `\r\n\r\n`，于是一条都切不开。
2. 一个事件里只取第一行 `data:`。SSE 规范允许续行，多行时参数被截断。
3. 流结束时把残留 buffer 直接丢掉。很多中转的最后一条事件不带结尾空行，最后那个 `tool_calls` 就没了。

后果是同一条链：**解析不出事件 → 工具调用列表恒为空 → agent 循环第一轮就返回 → 模型收不到工具结果，界面只显示一句聊天**。用户看到的就是「AI 说它记住了，其实什么都没发生」。

修复内容：

- 抽出 `parseSseBlock()`：多行 `data:` 按 `\n` 拼接；`delta`（流式分片）与 `message`（非流式整包）走同一出口，避免两套代码漂移。
- 抽出 `createSseParser()`：先做 `\r\n → \n` 归一化再切分，流结束时 `flush()` 把残留当事件处理。
- 上游忽略 `stream`、直接回完整 JSON 时，按非流式对象解析一次。
- 拿到字节却什么也没解析出来时，明确报「响应格式无法识别」，不再静默返回空内容。

## 升级说明

与 2.9.0 / 2.9.1 同一签名证书，**可直接覆盖安装，本地数据、配对令牌与登录态保留**。不需要重新配对，AI 的接口地址与 Key 也不用重填。

## 安装

1. 下载 `todo-link-2.9.2.apk`，允许「安装未知来源应用」。
2. 覆盖安装。
3. 打开 AI 页，说一句「明天下午三点交房租」，确认待办列表出现该条。

## 已知限制

- 若当前模型本身不支持函数调用（如部分推理模型），仍不会建待办——这类模型会明确报错，不会假装成功。换 `deepseek-chat` / `gpt-4o-mini` 一类支持 tools 的模型即可。
- 局域网内仍为明文 HTTP，令牌无过期机制（P1-18 未实现）。
- 番茄钟仍是固定 25/5 分钟，自定义时长与提醒时间设置随 3.0.0 一起做（见 `docs/11`）。
