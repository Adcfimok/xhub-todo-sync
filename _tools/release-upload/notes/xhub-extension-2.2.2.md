# 待办同步扩展 · x-hub v2.2.2

在 2.2.1 基础上修一个**兼容性风险**：本机接口不再强制自定义请求头。

## 为什么有这个版本

2.2.1 为了防 CSRF，要求 `/api/local/*`、`/api/admin/*` 必须带 `X-Hub-Local: 1`。
这个头由扩展页面自己加，但**它是经宿主 `service.request` 转发的，而宿主是否透传自定义头并不确定**。
一旦宿主不透传，扩展页面所有请求都会被 403 打死，等于装上去就用不了。

本版把判定改为只依赖浏览器强制写入、页面脚本无法伪造的两个头：

| 判定依据 | 谁写的 | 能否被页面伪造 |
| --- | --- | --- |
| `Sec-Fetch-Site: cross-site` | 浏览器 | 否 |
| `Origin` | 浏览器 | 否（脚本只能改 `referer` 之类，改不了 Origin） |

同源页面请求不带 `Origin`、`Sec-Fetch-Site` 为 `same-origin`，直接放行——**是否透传自定义头都不影响**。
跨站页面请求必然命中上面任一条，照样拒绝。防护强度不变，兼容面变大。

自定义头仍然接受（带了不冲突），只是不再是必要条件。

## 本版变更

- **本机接口判定改为 `Sec-Fetch-Site` / `Origin`**：不再强制 `X-Hub-Local`，避免因宿主不透传头而导致整页 403。
- **`/api/v1/diag` 同步调整**：跨站由 CORS 层直接拒绝（该接口含内网地址），同源可读，不再要求自定义头。
- 其余与 2.2.1 完全一致（24 项审计修复不变）。

## 从 2.2.1 升级

覆盖解压即可。如果你在 2.2.1 上遇到「页面能显示但数据一直加载失败、状态栏报 403」，
那正是本版修的问题，升级后即恢复。

## 验证

```bash
node run-all.mjs      # 端到端 41 通过 + 安全可靠性 28 通过
```

- `同源请求无需自定义头即可访问` —— 模拟宿主不透传头的情况，必须 200
- `跨站 Sec-Fetch-Site 被拒` —— 模拟恶意页面，必须 403
