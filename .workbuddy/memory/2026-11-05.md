## 交付：x-hub 待办同步（扩展 + 安卓 APK）

**做了什么**

- 逆向分析 x-hub（源码 v0.9.7 / 实机 0.9.1 便携版），产出架构与扩展机制分析。
- 提取工作台卡片适配规范：12 列网格、gap 16、行高下限 36、body padding 12、`container-type: size` + `cqh` + `clamp`，
  153×34 是最坏内容区。
- 写扩展 `com.zhou.todo-relay`（service 运行时，`0.0.0.0:47821`，network 权限），中枢在 Node 侧，
  前端只做宿主待办 ↔ 中枢的搬运。
- 安卓端 WebView 壳 + 本地资源 HTTP 服务（127.0.0.1 随机端口，拿安全上下文），assets/www 里是原生 JS 应用，
  IndexedDB 存数据，离线优先。
- 手动构建 APK（无 Gradle）：aapt2 → javac(8) → d8 → python 补 classes.dex → zipalign → apksigner。

**关键决策（后续别推翻）**

- 同步用 HLC + 记录级 LWW；不做字段级合并（宿主 update 全量覆盖、无历史版本）。
- 传输用 HTTP + SSE，不用 WebSocket（单向推送，免手写帧解析）。
- 固定端口 47821（方便手机记住、防火墙规则持久），`network` 权限必需。
- 安卓端 origin 必须是 http://127.0.0.1（安全上下文），不能走 file://，否则相机/存储受限。
- 冲突只在「上一版来自另一设备」时记录，否则宿主自身连续编辑会刷屏。

**踩过的坑**

- 后端进程残留会占用 47821，导致新实例静默起不来；测试前先确认监听进程。
- `applyHostSnapshot` 只有收到完整快照才允许推断删除（`full: true`），否则部分快照会误删。
- 手机编辑日期会把秒/毫秒抹平 → 日期时间未改动时保留原时间戳。
- 文件路径给 Windows 工具链时必须 `pwd -W`，不能用 MSYS 的 `/c/...`。
- 卡片矮尺寸下第 3 行会被裁半行 → 用容器查询显式隐藏，而不是靠 overflow。

## 追加：v2.4.1 数据"被覆盖"根因与修复（同日）

**根因**
- `AssetServer.start()` 用 `new ServerSocket(0)`，端口由系统随机分配；
  页面 origin = `http://127.0.0.1:<port>`，而 IndexedDB 按 origin 隔离。
  换端口 = 换一个空存储分区 → 数据"消失"（旧库仍在 `app_webview/Default/IndexedDB/http_127.0.0.1_<旧端口>.indexeddb.leveldb`）。
- 冷启动就会发生，不是升级导致；平时 App 常驻后台不重启，装新版本必然重启一次才暴露。
- 放大：meta 也空了 → token 为空 → 显示"未配对 + 空列表"，重新配对后又从电脑拉回来，掩盖真因。

**排除项**：升级不删私有目录；无 clearCache/deleteDatabase；DB_VER upgrade 只 create 不 delete；
allowBackup 无关。（次要风险：pullSnapshot 用快照整体替换，电脑端清空会连带清手机。）

**修复（v2.4.1）**
- 固定端口 47830–47833，`setReuseAddress(true)` 必须在 bind 之前（避开 TIME_WAIT）；
  全占用才回退 `bind(0)`。
- MainActivity 把上次端口存 SharedPreferences，变化时置 originSwitched，
  经桥暴露 `originChanged()/originPort()`；首页显示橙色提示条（不静默丢数据）。
- 编译踩坑：`server.getLocalPort()` 不是 AssetServer 的公开方法，补 `port()`。

**方案对比（写进 docs/06）**
- A 固定端口（采用）：改动极小，origin scheme 不变，无 mixed content 风险。
- B 固定 origin（`appassets.androidplatform.net`）：100% 保留，但 https origin 下
  `fetch('http://192.168.x.x:47821')` 会撞 `MIXED_CONTENT_NEVER_ALLOW`，必须先把 core.js::http 改走原生桥
  （好在它是唯一出口、且无 EventSource），否则同步全废。
- C 数据搬 SQLite：彻底但与 origin 无关，需重写数据层，暂不做。

**迁移**：配过电脑的重新配对即可拉回；纯本地未配对的找不回来（无枚举 origin 的 API、旧版无导出）。
→ 建议尽快补「导出/导入 JSON」+「快照骤降保护」。

**产物**：`android/todo-link-2.4.1.apk`（code 8）、`docs/06-数据保留与升级迁移.md`、
docs/04 新增 P1–P5 验收。

## 18:50 配对失败排查 + 读取权限（v2.8）

**现象**：PC 与手机同一 Wi-Fi（PC 10.11.53.185），扩展显示「服务就绪」，扫码/手输都超时。

**根因（五层叠加，不是网络问题）**
1. 主地址按网段猜 → 命中 VMware VMnet1 `192.168.21.1`（同机还有 VMnet8、VPN `vgate0`）。
2. 二维码 v2 只带一个地址，带的就是错的那个。
3. 手机端单地址 `await`，失败即整单失败，没有候选轮询。
4. `network` 权限未开时后端只监听 127.0.0.1，页面仍显示「就绪」。
5. `data.*.list` 抛 `PERMISSION_DENIED` 时只写 lastError，界面无解释无入口。

**改法**
- 新增 `service/netinfo.js`：UDP `connect(223.5.5.5:53)` 取默认路由出口；`rankAddresses()` 默认路由 1000 / 物理 +100 / 虚拟 -100，过滤 169.254。
- `/api/v1/diag` 暴露 primary/defaultRoute/addresses[].virtual/verdict。
- 页面：主地址标签「默认路由 · WLAN」、虚拟网卡灰显 + 「虚拟」、红条、权限按钮（`runtime.openPermissions`）。
- 二维码升 v3：`xhub://3/<code>/<ip:port,…>`，最多 4 个物理候选。
- 手机：新增 `lib/paircode.js`，v1/v2/v3 兼容；设置页逐个 `ping`+`pair`，按钮 `连接中… (2/4)`，配对码错/超限/设备满为终态。
- 权限红字一次列全被拒集合。
- **顺带修数据隐患**：空快照（rows=[]）不再打墓碑，页面连续两次读到空才带 `allowEmpty:true`。这就是「笔记莫名消失」的来源。

**验证**
- `verify-fix.mjs` 10 条断言全绿（PC 主地址/标签/二维码 v3/虚拟标记/无红条/范围说明；中枢 4/2/2/3/2；权限红字+按钮；手机配对 + 五类取数）。
- e2e 扩到 42 项（新增空快照保护 3 项），42/0。
- `paircode-test` 6/6、`netinfo-test` 5/5。
- 分发包解压到空目录实测 `/healthz`、`/api/v1/diag` 正常（旧包缺 netinfo.js，解压后起不来）。

`dist/com.zhou.todo-relay-2.1.0.zip`、`docs/04` §15、`docs/05` §13、`docs/03` §11、README 排障段、
