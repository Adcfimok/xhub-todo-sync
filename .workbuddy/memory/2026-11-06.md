# 2026-11-06

## 发布流程改造：一版一 Release（xhub-todo-sync）

**目标**：此后每个 APK / 扩展新版本，都要自动推送代码 + 建对应 Release（含版本说明与可下载产物），并保证代码与 Release 一致。

**改动**
- `_tools/release-upload/lib.mjs`：新增 `KIND_META`、`tagForEntry`、`releaseNameFor`、`notesRelPath`、`readNotes`、`renderFallbackNotes`、`isPrerelease`；`baseRecord` 透传 `tag/commit/notes/releaseName`；`executePlan` 支持 `notesFor` 兜底。
- `_tools/release-upload/adapters.mjs`：GitHub 适配器改为「一个版本一条 Release」，建 Release 前先 `POST /git/refs` 把标签钉到产物提交；正文取版本说明；预发布版本自动标 prerelease；422 并发回读。
- `_tools/release-upload/upload.mjs`：逐条解析标签/标题/说明/提交（`git log -1 -- <file>`，回退 `GITHUB_SHA`）。
- 新增 `verify.mjs`：四条一致性判定（Release 存在、资产同名、大小 + SHA-256、标签提交 == 产物提交），支持 `--offline`（git ls-remote，无需令牌）。
- 新增 `sync.mjs`：本地体检 / `--push` 登记新产物并推送，触发云端发布。
- `notes/`：补 `xhub-extension-2.1.0`、`android-apk-2.7.0`、`android-apk-2.8.0` 三份说明 + 写法约定。
- 工作流：`publish-releases.yml` 加 `fetch-depth: 0`、发布后自动校验并回写 `release-results/verify-latest.json`、校验不通过即失败；新增 `verify-releases.yml`（每日 09:00 巡检）。
- 文档：`docs/08-发布与版本同步流程.md`；README 增加「发布新版本」。

**结果**
- 标签 `xhub-ext-v2.1.0`、`android-v2.7.0`、`android-v2.8.0` 均指向 `376694d`（含产物的提交）。
- 三条 Release 建成，资产可下载；CI 校验 `ok: true`，drift 0 / warn 0。
- 单测 22 项通过。
- 自动化「每日检查新版本并同步到 GitHub Releases」已建（每天 10:00，`bbe43b0f`）。

**坑**
- `githubFacts` 里 `fetchImpl` 漏默认值，单测注入 fetch 掩盖了问题，CI 首跑才暴露 → 已修，补了附注标签解析测试。
- 工作流里 `[ -f x ] && cp` 在 `bash -e` 下会中断后续步骤 → 改成 `if [ -f ]; then ...; fi`。

**遗留**：`version-archive` 归档 Release 保留（旧链接不失效），新版本不再写入。
