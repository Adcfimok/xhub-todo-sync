# 2026-11-09

## 3.7.0 · 修复提醒延迟与「App 未打开收不到通知」

用户实测：系统通知有延迟；App 前台关闭 / 后台被终止后完全收不到。审查后确认根因不在通知构造，而在闹钟链路。

**根因（7 条）**
1. AlarmManager 闹钟一次性，`AlarmReceiver` 响完不补排，且只排最近 3 条 → 第 4 条起永不触发。
2. 待排提醒只存在 WebView 的 IndexedDB，原生无副本 → 进程被杀/重启即失联。
3. Manifest 无 `RECEIVE_BOOT_COMPLETED`、无开机接收器 → 重启一次手机后永久静默。
4. `SCHEDULE_EXACT_ALARM` 只声明不检查，静默退化为 `setAndAllowWhileIdle` → Doze 延迟。
5. `onRequestPermissionsResult` 只处理相机，`POST_NOTIFICATIONS` 结果被丢弃 → Android 13+ 被拒后一条弹不出。
6. 前台只靠 30s 轮询 + 15min 逾期宽限 → 慢且易漏。
7. 原生发通知不写 `notifiedMap` → 后台响过再开 App 又弹一次。

**改法**
- `Reminders.java` 重写：计划存 `SharedPreferences("xhub_reminders")`（key `plan`，上限 60 条），挂前 8 条（槽位 0..7）；计划文本未变则跳过重排（避免到点瞬间被撤）。
- `AlarmReceiver`：`goAsync()` + 10s PARTIAL_WAKE_LOCK → 通知 → 震动 → 记 `event` → `onFired()` 摘一条 + 补排下一条。
- `RestartReceiver`（新增）：BOOT_COMPLETED / QUICKBOOT_POWERON / MY_PACKAGE_REPLACED / TIME_SET / TIMEZONE_CHANGED → `rearmAfterRestart()`。
- 桥新增 `takeAlarmEvents / alarmState / testAlarm / openExactAlarmSettings / openNotificationSettings / requestNotifyPermission`。
- `lib/plan.js`（新增，纯函数）：`planItems / dueNow / nextDueAt / readAlarmEvents / trimFired`；`alerts.js` 改为精确 `setTimeout`（上限 60s）+ 对账 + 补发（12h 窗口，文案「补发 ·」）+ 关开关 `cancelAlarms`。
- 设置页「通知自检」：权限/精确闹钟/渠道/已排 四行状态 + 10 秒测试 + 三个补救入口。

**验证**：单测 153（新增 `alerts-plan` 25）；`_tools/notify-check.mjs` 26 项全绿；home 100、tab-gesture 22、school-list 17、app-shortcuts 28 回归通过。

## 锁屏收不到通知：根因定位与修复（P0）
- 现象：点「10 秒后测试提醒」→ 立刻锁屏 → 到点无任何通知。
- 根因：`alerts.js#scheduleAlarms()` 在 `plan.length===0` 时调 `cancelAlarms()` → 原生 `clearPlan()`（K_PLAN="[]" + 撤全部 8 槽）。自检条目只存在原生计划里，锁屏触发 visibilitychange → scheduleAlarms → 计划为空 → 刚排好的自检闹钟被撤。「此刻无计划」≠「用户关闭提醒」，语义混淆。
- 修复：① 空计划改 `setAlarms('[]')` 走差量，保留原生独有条目；② `MainActivity.onPause` 新增 `flushAlarms()`（WebView 息屏时不保证触发 visibilitychange，onChange 2.5s 防抖冻结后不再执行）；③ app.js 挂 `window.__flushAlarms`；④ `testIn` 按 tag 滤旧自检（原 drop(...,0) 回退条件 `it.at<=0` 永不成立，连点两次会 1 秒后误响）；⑤ notify 失败改 Log.w。
- 验证：`_tools/notify-check.mjs` 新增场景 3，在旧实现上跑出 29/30（红），修复后 30/30；`node --test` 153 全绿；build.sh 通过。
